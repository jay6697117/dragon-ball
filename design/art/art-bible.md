## 1. Visual Identity Statement

### 视觉总规则

《星核斗魂》的所有视觉都必须像“街机拳馆中的恒星能量训练者”：先让玩家看清拳脚距离、出招方向、防守状态和硬直窗口，再用星核能量强化情绪峰值；当“热血酷炫”和“格斗可读性”冲突时，永远选择可读性。

### 支持原则

#### 1. 拳脚先于能量

**定义：** 角色轮廓、站姿、攻击姿态、受击反馈和移动方向必须先表达清楚肉身格斗动作，能量光效只能强调发力、命中、爆气和反杀时刻，不能遮住拳脚和判定关系。

**绑定的游戏支柱：** 读招定胜负；气槽辅助，不接管战斗；热血能量必须可读。

**设计测试：** 当“更大的能量特效”与“更清楚的攻击前摇/攻击方向”冲突时，选择更清楚的攻击前摇/攻击方向；特效可以更亮、更集中、更有节奏，但不能更挡视线。

#### 2. 高对比读招剪影

**定义：** 每个关键战斗状态都要形成一眼可辨的剪影和色值关系：待机、前进、后退、防御、出招、被打、硬直、爆气必须在小尺寸 Web 画面中仍能区分。

**绑定的游戏支柱：** 读招定胜负；短连招，高回合；第一回合必须好玩。

**设计测试：** 当“更细腻的服装/身体细节”与“更明确的动作剪影”冲突时，选择更明确的动作剪影；玩家不需要理解设定，也必须能在第一回合看懂谁在进攻、谁在防守、谁露出破绽。

#### 3. 星核拳馆统一一切

**定义：** 场景、角色、UI、VFX 和光色都服务于同一个视觉锚点：一座街机感拳馆里的恒星能量训练场；视觉语言应使用训练器材、擂台边界、地面标线、能量核心、热辐射光和清晰 UI 层级，而不是复杂奇幻背景或现成动漫符号。

**绑定的游戏支柱：** 第一回合必须好玩；热血能量必须可读；气槽辅助，不接管战斗。

**设计测试：** 当“更宏大的宇宙奇观/动漫式夸张设定”与“更稳定的拳馆竞技空间”冲突时，选择更稳定的拳馆竞技空间；星核感应集中在灯光、材质、气槽和爆气瞬间，而不是让背景、服装或招式变成不可读的视觉噪声。

### 对 Web 60fps 与生成式资产管线的服务方式

这套视觉身份优先使用清晰剪影、有限色组、集中光效和重复可控的拳馆元素，能天然适配 Web 60fps 的性能目标：地图以稳定的 2.5D 拳馆空间、低复杂度背景层和明确地面参照为主，避免高密度动态背景抢占性能和注意力；角色与动画以少量高识别度关键姿态为核心，让 generate2dsprite 产出的精灵更容易保持一致轮廓、方向性和动作可读性；能量特效采用短时长、高对比、局部爆发的方式出现，既满足热血情绪峰值，也减少持续大面积透明叠加对浏览器渲染的压力。整体上，generate2dmap 负责统一“星核拳馆”的空间秩序，generate2dsprite 负责统一“恒星能量训练者”的角色动作语言，两条生成式资产路线都围绕同一条规则工作：先让战斗信息可读，再让能量把关键瞬间点燃。

## 2. Mood & Atmosphere

《星核斗魂》的整体情绪基调是“街机拳馆里的恒星能量训练”。每个画面都应该先服务格斗判断：玩家必须一眼看清拳脚距离、出招方向、防守状态、硬直窗口；星核能量只在情绪峰值、状态切换和奖励反馈中强化氛围。氛围可以热血、强烈、酷炫，但不能遮挡角色剪影、攻击轨迹、命中反馈和 UI 读数。

### 2.1 主菜单 / 进入拳馆前

- **Primary emotion / mood target**：即将踏入拳馆的期待感。玩家应感觉自己站在一间地下街机拳馆门口，里面有热血、训练、挑战和星核能量的低频脉动。
- **Lighting character**：整体偏冷暗，使用深蓝、紫黑作为环境底色；拳馆入口或标题区域有稳定的暖橙光，像门缝中透出的训练场灯光。对比度中高，但不刺眼。时间感接近夜晚或赛前闭馆时段。
- **Atmospheric descriptors**：神秘、蓄势、街机感、低频脉动、赛前兴奋。
- **Energy level**：Measured。能量处于收束状态，只暗示星核力量存在，不提前进入爆发。
- **承载氛围的视觉元素**：拳馆入口上方的星核霓虹招牌。招牌可有轻微呼吸式亮度变化，像恒星核心在慢慢跳动。
- **可读性注意事项**：主菜单按钮必须比背景霓虹更清晰。标题、开始按钮、当前选中项使用最高视觉层级；背景粒子、灯光闪烁和霓虹纹理不得与按钮高亮竞争。

### 2.2 训练木桩模式

- **Primary emotion / mood target**：安全、专注、可练习。玩家应感觉这里是拳馆内的基础训练区，可以放心观察距离、节奏、命中反馈和连招窗口。
- **Lighting character**：偏中性暖光，亮度稳定，阴影柔和。主光源来自拳馆顶部训练灯，角色和木桩轮廓清楚。对比度中等，避免过强的戏剧阴影。
- **Atmospheric descriptors**：清晰、稳定、朴素、可控、训练感。
- **Energy level**：Measured。星核能量只作为命中确认、气槽变化和训练反馈出现，不制造战斗压力。
- **承载氛围的视觉元素**：带有星核纹路的训练木桩。木桩被击中时纹路短暂亮起，用来确认命中点和打击节奏。
- **可读性注意事项**：木桩受击反馈必须清楚但短促，不能长时间发光遮挡角色拳脚。训练区域背景应低细节、低运动，方便玩家观察攻击距离和硬直恢复。

### 2.3 普通战斗状态

- **Primary emotion / mood target**：紧张、直接、读招驱动。玩家应感觉自己处在高回合制的拳馆对决中，每一次前进、出拳、防守和硬直都很重要。
- **Lighting character**：冷暖混合。场地底色偏冷，角色交战区使用暖色主光强化舞台中心。对比度高，角色剪影和攻击方向必须优先清楚。时间感像拳馆正式开打时的聚光灯环境。
- **Atmospheric descriptors**：紧绷、清楚、热血、对抗、节奏明确。
- **Energy level**：Tense。能量存在但受控，主要跟随攻击、格挡、命中和气槽积累做短促反馈。
- **承载氛围的视觉元素**：拳馆地面中央的星核擂台环。环形纹路在双方交战时轻微发亮，帮助把玩家视线集中到有效战斗区域。
- **可读性注意事项**：普通攻击的拳脚轮廓必须先于能量特效出现。攻击拖尾不得超过必要长度；格挡、受击、硬直和可行动恢复要有不同的姿态或轮廓差异，不能只靠颜色区分。

### 2.4 爆气反杀状态

- **Primary emotion / mood target**：濒危反扑、肾上腺素爆发。玩家应感觉星核能量被压缩到极限后瞬间点燃，但仍然能判断对手动作和反杀窗口。
- **Lighting character**：高对比、强暖光爆发。爆气瞬间可用金橙、白黄或炽红作为核心光，但背景应短暂压暗，让角色剪影更突出。光源感觉来自角色胸口、拳头或气槽核心，而不是全屏随机闪烁。
- **Atmospheric descriptors**：爆裂、危险、炽热、压迫、反转。
- **Energy level**：Explosive。能量达到最高强度，但只在启动、命中、取消或终结瞬间爆发；常驻阶段应降回可读强度。
- **承载氛围的视觉元素**：角色身后的星核爆气轮廓。它像一圈压缩恒星光环，强化角色状态，但不覆盖手、脚、头部和受击框判断区域。
- **可读性注意事项**：爆气特效不能遮挡对手起手动作。爆气状态必须有清晰边界：启动闪光、持续轮廓、结束回落三段要能被玩家区分。全屏震动、色散和粒子数量要克制，Web 版本优先使用少量高辨识度图形而不是大量粒子。

### 2.5 胜利状态

- **Primary emotion / mood target**：热血释放、训练成果被确认。玩家应感觉自己赢下了一回合拳馆挑战，而不是进入夸张的毁灭性终结。
- **Lighting character**：暖色上升，主光从擂台中心或角色前方打亮。背景可略微降细节，让胜利角色成为唯一焦点。对比度高但边缘柔和，时间感像赛后灯光集中到赢家身上。
- **Atmospheric descriptors**：昂扬、明亮、释放、自信、街机奖励感。
- **Energy level**：Celebratory。能量从爆发转为稳定外放，表现为短暂上扬的光、气焰或星核碎光。
- **承载氛围的视觉元素**：胜利者脚下的星核擂台光圈。光圈向外扩散一到两次，像拳馆承认本回合胜者。
- **可读性注意事项**：胜利反馈应明确但不拖长。结算文字、胜利提示和继续操作提示必须在最高层级；背景庆祝光效不得干扰 UI 文本读取。

### 2.6 失败状态

- **Primary emotion / mood target**：受挫但想再来一局。失败应该表达“这一回合没读对招”，而不是惩罚或羞辱玩家。玩家应清楚知道战斗结束，并愿意快速重试。
- **Lighting character**：亮度下降，色温转冷，暖色只保留在远处拳馆灯或对手胜利光中。对比度中等，避免把画面压到看不清。时间感像擂台灯光从自己身上移开。
- **Atmospheric descriptors**：沉静、失落、短暂冷却、可恢复、再挑战。
- **Energy level**：Low / Cooling。星核能量从角色身上退散，变成少量暗淡碎光或烟尘。
- **承载氛围的视觉元素**：玩家角色周围熄灭的星核碎片。碎片向下落或慢慢消散，表达能量中断。
- **可读性注意事项**：失败画面必须快速给出“重试 / 返回 / 继续”的清晰选项。不要使用长时间黑屏、强模糊或持续抖动；玩家需要立刻理解自己已经失败并知道下一步操作。

### 2.7 暂停 / 调试反馈状态

- **Primary emotion / mood target**：中断、检查、信息清楚。暂停状态应让玩家感觉战斗被冻结，可以安全阅读选项；调试反馈应像拳馆训练仪表，而不是破坏世界观的杂乱开发覆盖层。
- **Lighting character**：暂停时整体降饱和、降亮度，角色和关键 UI 保持清楚边缘。调试反馈使用冷色技术光，如青蓝、白色、淡绿，避免与战斗中的红橙爆气混淆。对比度以文本可读为第一优先。
- **Atmospheric descriptors**：冷静、清楚、冻结、技术化、可诊断。
- **Energy level**：Paused / Diagnostic。能量运动停止或变成极慢速脉冲；调试信息只表达状态，不制造情绪高潮。
- **承载氛围的视觉元素**：半透明星核训练 HUD 网格。它像拳馆训练系统投射出来的分析层，用于承载暂停菜单、命中框、距离线或状态文字。
- **可读性注意事项**：暂停菜单和调试文本必须压过所有背景元素。调试颜色不得复用关键战斗语义色，尤其不要把错误提示、命中框、气槽颜色和爆气颜色混在一起。若显示碰撞框或距离线，线条应细、纯色、无发光，避免误读为正式美术特效。

### 2.8 状态间氛围切换规则

- **主菜单 → 战斗**：从低频霓虹脉动切到擂台聚光，情绪从期待进入紧张。切换应短、直接，避免长加载式演出削弱第一回合节奏。
- **训练 → 普通战斗**：从稳定暖光提高对比度和环境压力，但保留同一拳馆材质语言，让玩家感觉训练和实战属于同一个地方。
- **普通战斗 → 爆气反杀**：允许最大视觉峰值，但必须先给清晰启动信号，再进入高能状态。任何全屏效果都应该短于玩家需要读招的关键窗口。
- **爆气 → 胜利 / 失败**：胜利把能量向外释放并变暖；失败把能量向下熄灭并变冷。二者都应快速回到可操作 UI。
- **任何状态 → 暂停 / 调试**：立即降低运动和饱和度，保留角色姿态与关键战斗信息，确保玩家恢复游戏时能重新读懂当前局面。

## 3. Shape Language

### 3.1 形状语言总原则

《星核斗魂》的形状语言必须服务一个核心判断：玩家能否在缩略图大小、快速移动、特效叠加和 Web 60fps 的限制下，立刻读懂“谁在攻击、攻击往哪去、距离是否够、防守是否成立、硬直何时出现”。

本项目的所有形状都应来自三组母题：

1. **拳馆结构形**：矩形、梯形、擂台边线、训练标线、器材框架。
   - **服务支柱**：星核拳馆统一一切。
   - **传达情绪**：稳定、训练感、可控、街机拳馆的实体重量。

2. **格斗动作形**：清晰肢体线、拳脚延展方向、重心三角、冲刺斜线、格挡弧面。
   - **服务支柱**：拳脚先于能量；高对比读招剪影。
   - **传达情绪**：直接、紧张、身体对抗、每一次出招都有力量来源。

3. **星核能量形**：压缩圆环、星芒切线、短弧尾迹、核心光点、爆发放射线。
   - **服务支柱**：星核拳馆统一一切；拳脚先于能量。
   - **传达情绪**：热血、峰值、反杀、能量被训练系统约束后的酷炫。

**硬规则**：能量形不能盖过格斗动作形。任何星芒、光环、尾迹和冲击波都必须围绕拳脚方向、受击点和攻防状态组织，而不是独立表演。

### 3.2 Character Silhouette Philosophy

#### 3.2.1 缩略图可读性

角色在小尺寸缩略图、快速移动和特效覆盖下，必须仍然能读出以下信息：

- 头部位置：玩家要能立刻判断角色朝向和身高中心。
- 肩线和髋线：用于判断角色是否正在前压、后撤、下蹲或起跳。
- 拳脚端点：出招时手、脚、膝、肘必须成为剪影上最容易定位的点。
- 防守轮廓：格挡状态必须形成紧凑、封闭、稳定的形状。
- 硬直轮廓：受击或收招时，身体线条要明显失衡，让玩家知道这是可追击窗口。

**形状原则**：角色剪影优先使用“稳定躯干 + 明确四肢端点 + 可识别重心线”。躯干可以厚实，四肢端点必须干净，不能被头发、衣摆、能量火焰或复杂饰件打乱。

- **服务支柱**：高对比读招剪影；拳脚先于能量。
- **传达情绪**：公平、清楚、扎实，让玩家觉得输赢来自读招和反应，而不是视觉混乱。

#### 3.2.2 均衡武斗家轮廓规则

第一版均衡武斗家应采用“中等体块、稳定重心、拳脚端点突出”的轮廓。

推荐轮廓结构：

- **头部**：简洁圆角块面或短发轮廓，避免高耸尖刺。
- **肩部**：略宽于髋部，形成可信的格斗架势。
- **躯干**：清晰倒梯形或软化矩形，表达训练者的稳定核心。
- **手臂**：前臂和拳套/护手可以略放大，增强拳击距离读取。
- **腿部**：小腿和脚部端点清楚，踢击时脚尖方向必须明显。
- **站姿**：默认形成轻微三角支撑，下盘稳定但不笨重。
- **爆气状态**：不改变基础轮廓，只在身体外侧增加受控星核光环和短弧，不让角色变成另一种剪影。

禁止做法：

- 禁止七龙珠式尖刺发型、放射状巨大发束或高耸发冠。
- 禁止复刻橙蓝道服、龟派符号、赛亚人战甲等可识别 IP 服装结构。
- 禁止靠夸张头发和服装飘带制造主轮廓。
- 禁止让能量火焰长期包住手脚端点。
- 禁止在常态轮廓上堆太多徽章、挂件、绑带和外扩装饰。

替代方向：

- 使用“街机拳馆训练者”的装备语言：护手、轻量护肩、训练背心、压缩护具、星核能量计量带。
- 使用“星核训练系统”的原创符号：胸口或腰侧的小型核心节点、腕部环形能量槽、鞋底短弧推进线。
- 发型保持短、中短或贴合头型的动感轮廓，用局部高光和运动姿态表达热血，而不是用尖刺发型表达强大。

- **服务支柱**：星核拳馆统一一切；高对比读招剪影。
- **传达情绪**：原创、可信、年轻热血，但仍然是拳馆里的训练者，不是对既有经典动漫形象的复刻。

### 3.3 Environment Geometry

星核拳馆环境必须用几何结构支持战斗读取。背景不能抢角色，场景不能把攻击方向、地面距离和角色剪影变得难读。

#### 3.3.1 主导几何形状

星核拳馆的主导几何为：

- **擂台矩形/梯形**：提供空间边界、站位参照和街机格斗感。
- **星核圆环**：用于能量训练设备、擂台中心、背景反应炉和胜利光圈。
- **训练标线**：水平线、距离刻度、对角冲刺线，用来帮助玩家读距离。
- **结构框架**：门框、梁柱、护栏、器材架，用稳定直线压住能量特效的躁动。

整体比例应为“直线拳馆结构为主，圆环星核符号为辅”。圆环代表能量源，矩形和梯形代表训练秩序。

- **服务支柱**：星核拳馆统一一切；拳脚先于能量。
- **传达情绪**：这里是被训练、被测量、被点燃的格斗空间，不是抽象宇宙背景。

#### 3.3.2 擂台与地面标线

擂台是最重要的环境形状，必须优先保证角色脚下信息清楚。

规则：

- 地面主平面使用低饱和、低细节的大块面。
- 战斗区域边缘使用清晰矩形或梯形轮廓，避免破碎复杂边界。
- 中央可使用压低亮度的星核圆环，但不能比角色脚底和攻击特效更亮。
- 地面距离标线可以使用细线、短刻度或半透明训练网格，帮助判断前后距离。
- 角色脚下接触阴影必须比装饰纹样更重要。
- 爆气反杀时，地面星核圆环可以短时亮起，但亮度峰值应集中在角色周围，不能全屏均匀发光。

- **服务支柱**：高对比读招剪影；星核拳馆统一一切。
- **传达情绪**：专业、紧张、可测量，让玩家像在训练场中读距离和窗口。

#### 3.3.3 训练器材

训练器材应强化“拳馆”和“星核训练系统”的可信度，但必须退居背景。

推荐形状：

- 木桩/沙袋：竖向圆柱或圆角矩形，稳定、厚重、易识别。
- 能量靶机：圆环靶心 + 矩形支架，体现星核科技被固定在训练设备中。
- 墙面计量屏：扁平矩形，显示低亮度网格或脉冲线。
- 器材架：横竖直线为主，不使用过多斜线，避免与攻击方向混淆。

训练器材不能使用和角色攻击特效相同强度的星芒、尾迹或爆发线。它们可以发光，但只能低频、低对比、低饱和。

- **服务支柱**：星核拳馆统一一切。
- **传达情绪**：安全、专注、可训练，特别服务训练模式的稳定暖光氛围。

#### 3.3.4 背景层次

背景形状按重要度分三层：

1. **战斗读取层**：地面、脚底阴影、擂台边界、距离标线。最高优先级，但低装饰。
2. **拳馆身份层**：训练器材、护栏、墙体、门框、能量计量屏。中等优先级，低亮度。
3. **星核氛围层**：远景反应炉、霓虹、星点、光雾。最低优先级，只做情绪。

所有背景层都必须使用较低对比度，给角色、HUD和VFX让出视觉焦点。

- **服务支柱**：拳脚先于能量；星核拳馆统一一切。
- **传达情绪**：沉浸但不干扰，酷炫但不抢戏。

### 3.4 UI Shape Grammar

UI应像“星核拳馆训练系统”的可视化界面，而不是普通科幻面板或纯动漫血条。它要同时呼应拳馆结构和星核能量，但优先保证战斗信息一眼可读。

#### 3.4.1 HUD总规则

HUD使用三类基础形状：

- **矩形条**：血量、状态时间、调试数值，表达稳定、可量化。
- **分段槽**：气槽、能量段、训练计数，表达积累和消耗。
- **圆环/核心点**：爆气、反杀、关键能量峰值，表达星核激活。

HUD不应大量使用复杂斜切、过细边框或高频装饰。边缘可以有少量斜切来体现街机动感，但主读取区域必须保持横向清晰。

- **服务支柱**：高对比读招剪影；星核拳馆统一一切。
- **传达情绪**：可靠、清楚、像训练设备一样即时反馈。

#### 3.4.2 血条形状

血条应使用长矩形或轻微斜切长条。

规则：

- 主血量为最清晰、最长、最稳定的UI形状。
- 损失血量可使用短暂延迟残影条，但残影不能比当前血量更亮。
- 血条端点要清楚，方便玩家判断剩余比例。
- 不使用复杂弯曲血条，因为弧形比例更难快速读取。

- **服务支柱**：拳脚先于能量；高对比读招剪影。
- **传达情绪**：紧张、直接、公平。

#### 3.4.3 气槽/星核能量槽形状

气槽可以比血条更有星核识别度，但仍然必须可计数。

推荐形状：

- 分段矩形槽作为主体，确保玩家能数清资源。
- 每段内部可有小型核心光点或短弧填充，表达能量充入。
- 满槽时出现压缩圆环或核心闪点，但只短时出现，不持续闪烁干扰。
- 爆气反杀可让气槽边缘形成短暂星核环，但不改变槽体读数。

- **服务支柱**：星核拳馆统一一切；拳脚先于能量。
- **传达情绪**：积蓄、临界、准备反击。

#### 3.4.4 按钮提示形状

按钮提示应像训练系统给出的动作指令。

规则：

- 使用圆角矩形或小型胶囊形承载按键名称。
- 方向输入可用清晰箭头或短斜线，不使用复杂符号。
- 攻击按钮提示可配合拳/脚小图标，但图标必须非常简化。
- 关键提示如“格挡”“反击”“爆气”可加细圆环或短星芒强调。

- **服务支柱**：高对比读招剪影；星核拳馆统一一切。
- **传达情绪**：教学清晰、训练中、可执行。

#### 3.4.5 暂停/调试层形状

暂停和调试层应使用半透明星核训练 HUD 网格。

规则：

- 大面板使用低饱和深色矩形，保证文本可读。
- 背景覆盖层可使用细网格、距离刻度和圆环节点。
- 调试信息用表格式矩形模块排列，避免散乱浮动。
- 高亮选中项使用清晰描边或左侧能量条，不使用大面积闪烁。

- **服务支柱**：星核拳馆统一一切。
- **传达情绪**：冷静、技术化、可分析，符合暂停/调试的低情绪状态。

### 3.5 Hero Shapes vs Supporting Shapes

形状层级必须明确：哪些形状负责吸引视线，哪些形状负责退后支撑。

#### 3.5.1 Hero Shapes

Hero Shapes只用于玩家必须立刻注意的对象：

- 角色当前攻击肢体的外轮廓。
- 受击点的冲击形状。
- 爆气反杀的压缩星核环。
- 低血量、满气、可反击等关键HUD状态。
- 胜利瞬间的擂台光圈。

Hero Shapes的特征：

- 高对比。
- 轮廓干净。
- 方向明确。
- 存在时间短。
- 通常靠近角色、攻击路线或关键HUD。

常用形状：尖锐短星芒、压缩圆环、强方向斜线、清晰拳脚端点、聚焦光点。

- **服务支柱**：拳脚先于能量；高对比读招剪影。
- **传达情绪**：爆发、危险、机会、胜负瞬间。

#### 3.5.2 Supporting Shapes

Supporting Shapes用于建立世界观、空间感和节奏，但不能抢读招。

包括：

- 背景墙体和梁柱。
- 训练器材轮廓。
- 地面低亮度网格。
- 远景星核霓虹。
- 非关键UI边框。
- 常驻能量微光。

Supporting Shapes的特征：

- 低对比。
- 大块面。
- 慢节奏。
- 低饱和。
- 不和攻击方向使用相同强度的斜线。

- **服务支柱**：星核拳馆统一一切。
- **传达情绪**：沉浸、稳定、训练场的空间可信度。

#### 3.5.3 层级冲突规则

当多个形状同时出现时，优先级如下：

1. 攻击/防守/受击读招形状。
2. 角色剪影和脚底接触信息。
3. 关键HUD状态。
4. 角色星核能量状态。
5. 擂台边界和地面标线。
6. 背景器材和氛围光。

如果某个辅助形状让玩家更难看清前两级，必须降低亮度、降低细节、降低饱和度或移出角色附近。

- **服务支柱**：高对比读招剪影；拳脚先于能量。
- **传达情绪**：公平、秩序、清楚。

### 3.6 VFX Shape Rules

VFX必须区分轻击、重击、气弹、防御、爆气反杀。区别不只靠颜色，也要靠形状、持续时间、边缘硬度和运动方向。

#### 3.6.1 轻击 VFX

轻击使用短、小、硬边缘的方向形。

形状规则：

- 小型斜切闪线。
- 短弧尾迹。
- 细小冲击星点。
- 出现时间极短。
- 不形成大面积圆环或爆炸。

视觉重点应放在拳脚端点，帮助玩家读出攻击方向和距离。

- **服务支柱**：拳脚先于能量；高对比读招剪影。
- **传达情绪**：快速、利落、试探、节奏启动。

#### 3.6.2 重击 VFX

重击使用更厚、更慢、更有压迫感的形状。

形状规则：

- 宽斜线或楔形冲击块。
- 较大的受击爆点。
- 短暂压缩圆环表示力量集中。
- 拖尾可以更粗，但不能遮住角色上半身和拳脚端点。
- 起手阶段可有轻微蓄力形，但必须清楚显示攻击方向。

重击形状要让玩家感到“这一击有重量”，同时给出反应窗口。

- **服务支柱**：高对比读招剪影；拳脚先于能量。
- **传达情绪**：压迫、危险、重心转移、可惩罚的承诺感。

#### 3.6.3 气弹 VFX

气弹使用“核心点 + 外环 + 方向尾迹”的结构。

形状规则：

- 核心必须清楚，玩家要知道气弹的真实碰撞中心。
- 外环可以表达星核能量，但不能让判定范围看起来比实际更大。
- 尾迹沿飞行方向拉伸，帮助读取速度和轨迹。
- 普通气弹外形偏圆，强化可识别弹体。
- 强化气弹可增加一层压缩圆环或星芒切线，但仍保留清楚核心。

- **服务支柱**：星核拳馆统一一切；高对比读招剪影。
- **传达情绪**：能量被投射、可预判、可躲避或防御。

#### 3.6.4 防御 VFX

防御使用稳定、封闭、贴身的保护形。

形状规则：

- 贴近角色身体的半圆弧或短盾面。
- 低厚度描边，不做大面积能量罩。
- 受击时出现短暂压缩波纹，表示防住了冲击。
- 防御形状必须比攻击爆点更稳定、更少尖角。
- 破防或硬直时，封闭形状应断裂成几段，让状态变化一眼可读。

- **服务支柱**：拳脚先于能量；高对比读招剪影。
- **传达情绪**：稳住、承受、判断正确；破防时传达失衡和危险。

#### 3.6.5 爆气反杀 VFX

爆气反杀是最强的星核视觉峰值，但必须短、集中、可读。

形状规则：

- 以角色核心为中心出现压缩圆环，先内收再外放。
- 圆环边缘可带短星芒，但星芒不能变成长时间火焰。
- 角色拳脚端点必须始终可见。
- 爆发瞬间可以提高背景暗度，形成剪影反差。
- 冲击方向用强斜线或扇形冲击面表达，不能只是全屏亮光。
- 爆气结束后，残留形状快速退回低亮度核心微光。

爆气反杀不能让玩家失去对距离、防守状态和硬直窗口的判断。它的目标是把情绪推到峰值，同时仍然让玩家看懂“反杀从哪里开始、打到哪里、何时结束”。

- **服务支柱**：拳脚先于能量；高对比读招剪影；星核拳馆统一一切。
- **传达情绪**：濒危反击、恒星压缩后爆发、热血释放、逆转希望。

### 3.7 Shape Language Do / Don’t

#### Do

- 用清晰拳脚端点表达攻击距离。
- 用稳定矩形和梯形建立拳馆秩序。
- 用圆环、核心点和短星芒表达星核能量。
- 用低对比背景衬托角色和VFX。
- 用分段槽和明确条形保证HUD读数。
- 用短时高对比制造爆发，而不是长期全屏发光。

#### Don’t

- 不用尖刺发型、经典道服或可识别战斗动漫IP轮廓。
- 不让能量火焰吞掉拳脚动作。
- 不让背景霓虹和训练器材抢角色剪影。
- 不用复杂弧形血条降低读取效率。
- 不让气弹外环误导真实判定范围。
- 不把爆气反杀做成持续遮屏特效。

本节的最终判断标准：如果去掉颜色，只看黑白剪影和几何层级，玩家仍然应该能分辨角色状态、攻击方向、空间距离和关键能量峰值。

## 4. Color System

### 4.1 色彩系统总原则

《星核斗魂》的色彩系统必须服务于“读招定胜负”。颜色不是单纯装饰，而是帮助玩家快速判断距离、状态、危险等级、能量峰值和战斗节奏的视觉语言。

核心规则如下：

1. **可读性优先于酷炫度**
   当高饱和能量色、光效、渐变或闪烁影响角色剪影、拳脚方向、攻防状态、硬直窗口时，必须降低颜色强度、缩小覆盖面积或缩短显示时间。

2. **世界色彩统一为“深色拳馆 + 恒星能量”**
   基础环境以深蓝黑、冷铁灰、低饱和暗金为主，形成硬派训练馆氛围；情绪峰值由金白、琥珀、深红、紫边和少量青色信号点亮。不得随意加入与拳馆体系无关的大面积彩虹色、赛博霓虹堆叠、魔法森林绿、太空糖果色。

3. **角色本体与能量特效必须分层**
   角色身体、服装、拳脚轮廓使用相对稳定、低到中饱和的颜色；星核能量、命中反馈、爆气、UI 提示使用高对比色。玩家第一眼应先读到“人在做什么”，第二眼才感到“能量有多强”。

4. **高饱和色只用于短时、局部、关键信息**
   高亮金白、警戒红、青色反馈等颜色不得长期铺满画面。它们只能用于起手提示、命中瞬间、能量槽变化、反杀爆点、训练反馈等需要玩家立刻注意的位置。

5. **同类信息使用同类色温**
   - 暖色：攻击、爆发、胜利、能量释放、危险峰值。
   - 冷色：防御、冷却、失败、菜单等待、训练理性反馈。
   - 中性色：环境主体、擂台地面、非交互装置、普通背景层。

6. **禁止用颜色单独承载关键信息**
   所有重要状态必须同时有颜色以外的备份：形状、图标、轮廓、动画节奏、屏幕震动、音效或文字提示。尤其是危险、安全、防御、受击、冷却、可行动状态，不得只靠红绿或蓝黄区分。

### 4.3 Semantic Color Usage

#### 危险 / 即将受击

- **主色**：深红冲击 `#B93A46`
- **辅助色**：核心金白 `#FFF5C8` 的短帧闪点
- **用途**：敌方强攻击起手提示、破防预警、低血量警示、高伤害命中瞬间、不可防或特殊危险动作的边缘提示。
- **视觉规则**：
  - 危险提示使用尖角、斜切、外扩脉冲。
  - 不得只用红色表示危险，必须搭配尖锐形状、短促闪烁或音效。
  - 危险色不能长期覆盖角色身体，否则会破坏读招。

#### 可行动 / 安全 / 成功输入

- **主色**：冷青信号 `#39D6C8`
- **辅助色**：冷铁蓝灰 `#263241`
- **用途**：训练模式输入成功、可行动窗口提示、防御后恢复、成功闪避或成功取消窗口。
- **视觉规则**：
  - 使用短线、圆角小节点、清晰勾形或细边框。
  - 不得使用大面积纯绿色作为“安全”，避免红绿色盲误读。
  - 冷青只作为系统性反馈，不应成为角色主服装的大面积主色。

#### 防御 / 格挡 / 稳定

- **主色**：冷铁蓝灰 `#263241`
- **高亮**：冷青信号 `#39D6C8`
- **用途**：格挡状态边缘光、防御成功反馈、防御硬直中的 UI 提示、护盾式训练反馈。
- **视觉规则**：
  - 防御色温偏冷，形状偏硬边、半环、短盾形。
  - 防御效果必须贴近手臂、身体前方或防守方向，不得变成包住全身的大球。
  - 防御成功可以有冷青短闪，但不能比强攻击命中更抢眼。

#### 受击 / 硬直 / 破防

- **主色**：深红冲击 `#B93A46`
- **核心闪点**：核心金白 `#FFF5C8`
- **阴影补色**：擂台蓝黑 `#090D18`
- **用途**：受击点、击退拖影、破防裂纹、硬直状态提示。
- **视觉规则**：
  - 命中核心可以金白一闪，但随后应迅速回到深红冲击和暗色残影。
  - 受击反馈优先标出“哪里被打中”和“身体往哪里飞”，不得用能量爆炸盖住动作结果。
  - 破防使用裂纹、断线、碎片形状辅助识别。

#### 能量 / 蓄力 / 爆气

- **待机能量**：暗金待机灯 `#C28A38`
- **蓄力能量**：星核金 `#FFE76A`
- **峰值核心**：核心金白 `#FFF5C8`
- **反杀边缘**：深红冲击 `#B93A46` 或低饱和紫红阴影
- **用途**：气槽增长、蓄力动作、爆气瞬间、强攻击强化、反杀状态。
- **视觉规则**：
  - 能量由暗金到星核金再到金白，代表强度上升。
  - 爆气必须是短时、局部、高对比；不允许长期全身金焰常驻。
  - 能量形围绕拳脚、受击点和动作方向组织，不能独立表演。
  - 禁止形成经典蓝白直线能量波主视觉。

#### 奖励 / 胜利 / 正反馈

- **主色**：星核金 `#FFE76A`
- **辅助色**：暗金待机灯 `#C28A38`
- **峰值点**：核心金白 `#FFF5C8`
- **用途**：胜利结算、连击成功、训练目标完成、完美防御或精准反击奖励。
- **视觉规则**：
  - 胜利色温偏暖，但亮度要比爆气反杀低。
  - 胜利画面应表现“余温”和“站稳”，不是继续爆炸。
  - 金白只用于标题闪点、角色边缘或短暂粒子，不得铺满整屏。

#### 失败 / 冷却 / 不可行动

- **主色**：擂台蓝黑 `#090D18`
- **辅助色**：冷铁蓝灰 `#263241`
- **低亮暗金**：`#C28A38` 降低亮度后使用
- **用途**：失败画面、技能冷却、气槽耗尽、倒地后暂不可行动。
- **视觉规则**：
  - 失败不是纯黑，而是能量熄灭后的冷暗。
  - 冷却状态用低亮、低饱和、断线或收缩动画表示。
  - 不可行动必须有图标、灰度变化或动画冻结辅助，不能只靠颜色变暗。

### 4.4 Area / State Color Temperature Rules

#### 主菜单

- **色温**：低色温、低饱和、深蓝黑为主。
- **主色组合**：擂台蓝黑 `#090D18` + 冷铁蓝灰 `#263241` + 暗金待机灯 `#C28A38`
- **情绪目标**：夜间拳馆开灯前的压抑期待。
- **规则**：
  - 主菜单不使用爆气级金白。
  - 暗金只作为按钮焦点、灯带和星核装置弱光。
  - 背景应安静，避免主菜单已经进入战斗爆发状态。

#### 训练木桩

- **色温**：中性偏冷，局部冷青反馈。
- **主色组合**：冷铁蓝灰 `#263241` + 低亮暗金 + 冷青信号 `#39D6C8`
- **情绪目标**：清醒、干净、可学习。
- **规则**：
  - 输入反馈、距离提示、命中判定可使用冷青。
  - 木桩受击可使用低强度深红，但不能像正式战斗一样强烈。
  - 训练画面要减少情绪光污染，帮助玩家看清规则。

#### 普通战斗

- **色温**：暖侧光 + 冷阴影，高对比但可控。
- **主色组合**：擂台蓝黑 `#090D18` + 冷铁蓝灰 `#263241` + 星核金 `#FFE76A` + 深红冲击 `#B93A46`
- **情绪目标**：紧张、硬派、可控。
- **规则**：
  - 环境保持深色后退，角色和攻击反馈前置。
  - 攻击峰值使用暖色，防御和恢复使用冷色。
  - 单次 VFX 的高亮面积不得超过角色主体可读区域。

#### 爆气反杀

- **色温**：极高对比，核心极暖，边缘偏深红或紫红。
- **主色组合**：核心金白 `#FFF5C8` + 星核金 `#FFE76A` + 深红冲击 `#B93A46` + 深色负空间
- **情绪目标**：短促恒星爆裂，瞬间逆转。
- **规则**：
  - 金白核心只能短时出现。
  - 爆气不能变成持续金焰包身，也不能遮住姿势。
  - 边缘可用深红或低饱和紫红强调危险，但不得形成可识别现成动漫变身形象。
  - 爆气结束后必须迅速回落到普通战斗色温。

#### 胜利

- **色温**：温暖但不刺眼。
- **主色组合**：暗金待机灯 `#C28A38` + 星核金 `#FFE76A` 的低强度版本 + 深色背景
- **情绪目标**：释放、余温、站稳。
- **规则**：
  - 胜利不再使用大量深红危险色。
  - 金色偏柔和，表现“热量还在”，不是“继续爆炸”。
  - 角色剪影仍要清楚，避免胜利光效吞掉站姿。

#### 失败

- **色温**：冷、低饱和、能量熄灭。
- **主色组合**：擂台蓝黑 `#090D18` + 冷铁蓝灰 `#263241` + 极低亮暗金残光
- **情绪目标**：身体还在，能量熄灭。
- **规则**：
  - 不使用鲜艳红色铺屏，避免失败画面变成危险提示。
  - 气槽、角色边缘、环境灯逐步降亮。
  - 失败反馈应清楚但克制，不羞辱玩家。

#### 暂停 / 调试

- **色温**：中性偏冷，功能优先。
- **主色组合**：半透明擂台蓝黑遮罩 + 冷铁蓝灰面板 + 冷青信号重点
- **情绪目标**：功能性、克制、清楚。
- **规则**：
  - 暂停 UI 不抢战斗视觉，不使用爆气金白。
  - 调试信息可使用冷青、白字、灰线。
  - 警示项才使用深红冲击，且必须配文字或图标。

### 4.5 UI Palette

UI 可以比世界色彩更清晰、更规整，但不能完全脱离“星核拳馆”体系。HUD、菜单和训练反馈应看起来像拳馆能量仪表，而不是现代手机 App、科幻飞船面板或通用网页 UI。

#### HUD 血条

- **建议色彩**：
  - 当前生命：暖暗红到深红冲击 `#B93A46`
  - 受伤延迟条：低亮暗金 `#C28A38`
  - 血条底板：冷铁蓝灰 `#263241`
  - 危急闪点：核心金白 `#FFF5C8` 短帧
- **规则**：
  - 血量减少必须有长度变化，不能只变色。
  - 低血量可以使用深红脉冲，但必须控制频率，避免干扰读招。
  - 延迟扣血条用于帮助玩家理解伤害量，颜色要比当前生命更暗。

#### 气槽 / 星核能量槽

- **建议色彩**：
  - 空槽：冷铁蓝灰 `#263241`
  - 充能：暗金待机灯 `#C28A38`
  - 可用：星核金 `#FFE76A`
  - 满槽 / 爆气可触发：核心金白短闪 + 星核金主体
- **规则**：
  - 气槽必须有分段、刻度或形状变化，不能只靠亮度判断。
  - 满槽提示可以闪，但不能持续大面积闪烁。
  - 气槽爆发反馈应与角色爆气色彩一致，但 UI 亮度要低于角色动作核心。

#### 输入 / 训练反馈

- **建议色彩**：
  - 成功输入：冷青信号 `#39D6C8`
  - 错误输入：深红冲击 `#B93A46`
  - 中性提示：冷铁蓝灰 `#263241` + 白字
  - 完成目标：星核金 `#FFE76A`
- **规则**：
  - 输入反馈必须同时有文字、图标或方向符号。
  - 成功与失败不能只靠冷青 / 深红区分，必须使用不同形状：成功用勾形、短线闭合；失败用叉形、断裂、抖动。
  - 训练提示优先清楚，不追求华丽。

#### 菜单

- **建议色彩**：
  - 背景：擂台蓝黑 `#090D18`
  - 面板：冷铁蓝灰 `#263241`
  - 默认文字：低饱和浅灰或暖白
  - 当前选择：暗金待机灯 `#C28A38`
  - 确认 / 开始：星核金 `#FFE76A`
- **规则**：
  - 菜单高亮不使用纯白大面积发光。
  - 当前选择必须有切角边框、位置变化或短线动画。
  - 不得只用颜色区分“选中”和“未选中”。

#### 警示

- **建议色彩**：
  - 一般警示：深红冲击 `#B93A46`
  - 严重警示：深红冲击 + 核心金白短闪
  - 系统调试警示：深红边框 + 明确文字
- **规则**：
  - 警示必须搭配尖角图标、感叹号、闪烁节奏或音效。
  - 不允许用大面积红色遮挡战斗画面。
  - 训练模式中的警示要比正式战斗更克制，避免制造误判压力。

#### UI 是否允许偏离世界色彩

允许轻微偏离，但只限于**提高可读性**：

- 可以使用更清晰的浅灰、白字和更稳定的冷青。
- 可以提高 UI 边框和文字对比度。
- 不可以引入与世界观无关的高饱和紫、纯绿、纯蓝、粉色、彩虹渐变作为主要 UI 语言。
- 不可以让 UI 看起来比角色攻击和受击反馈更重要。

### 4.6 Colorblind Safety

《星核斗魂》不得依赖单一颜色传达关键战斗信息。所有重要信息必须有颜色以外的备份。

#### 红绿色盲风险

容易失败的组合：

- 深红危险 vs 绿色安全
- 红色错误 vs 绿色正确
- 红色低血量 vs 绿色满血
- 红色敌方提示 vs 绿色己方提示

解决方式：

- 安全 / 可行动不使用纯绿色，改用冷青信号 `#39D6C8`。
- 危险使用尖角、外扩脉冲、抖动、短促音效。
- 成功使用勾形、闭合线、上扬音效。
- 失败使用叉形、断裂线、短促下坠音效。
- 血量必须依靠条长、刻度、数字或头像状态，不只靠颜色。

#### 蓝黄色盲风险

容易失败的组合：

- 冷青反馈 vs 星核金奖励
- 蓝灰冷却 vs 暗金待机
- 金色满槽 vs 青色可行动

解决方式：

- 星核金奖励使用放射短线、星核小闪点、上升粒子。
- 冷青反馈使用细线框、勾形、输入方向符号。
- 冷却使用灰化、收缩、断线、倒计时或图标遮罩。
- 满槽使用分段填满、外框闭合、短促脉冲，不只靠金色。

#### 高亮 / 闪烁风险

- 不使用长时间高频闪烁。
- 核心金白 `#FFF5C8` 只能短帧出现。
- 爆气、命中、警示的闪烁必须控制在局部区域。
- 对 Web 玩家，避免整屏白闪、整屏红闪和连续强闪。

#### 必备非颜色备份

每类关键信息至少需要一个非颜色备份：

| 信息 | 非颜色备份 |
|---|---|
| 危险 | 尖角、外扩脉冲、警示音、敌方起手姿势 |
| 可行动 | 勾形、短线闭合、角色恢复站姿、轻提示音 |
| 防御成功 | 半盾形、碰撞火花方向、低沉格挡音 |
| 受击 | 击退方向、身体抖动、命中停顿、打击音 |
| 能量满 | 槽体闭合、刻度填满、短脉冲、低频蓄能音 |
| 冷却 | 灰化、收缩、倒计时、断线图标 |
| 胜利 | 角色站稳姿势、胜利标题、暖色余光、音乐收束 |
| 失败 | 角色倒地 / 低姿态、能量熄灭、冷色降亮、音乐压低 |

### 4.7 IP Safety

《星核斗魂》的色彩系统必须保持原创，不能复刻、暗示或组合出现可识别的现成动漫 IP 视觉记忆。以下规则为硬性禁止。

#### 禁止橙蓝主角配色

不得将主角设计为大面积橙色服装 + 蓝色内搭 / 腰带 / 护腕 / 靴子组合。

如果角色需要热血感，应使用原创的暗金、深红、冷铁灰、低饱和布料色进行组合，并通过拳馆训练装备和星核能量体现力量，而不是依赖经典橙蓝英雄识别。

#### 禁止金发金焰变身

不得出现以下组合：

- 头发变成高饱和金色。
- 全身持续金色火焰。
- 竖起尖刺状金发剪影。
- 金色爆气长期包裹全身。
- 变身后整体从服装到能量都变成强金色主视觉。

星核爆气可以使用金白核心和星核金，但必须是短时、局部、围绕动作和受击点的能量峰值，不是发型或身体形态的长期变色。

#### 禁止蓝白经典气功波主视觉

不得将核心招式设计为双手前推、蓝白直线大光束、长时间横向贯穿画面的经典构图。

若需要远程能量攻击，应优先使用原创形态，例如：

- 拳脚带出的短距星核冲击。
- 贴地半弧能量刃。
- 受击点局部恒星爆裂。
- 训练装置引导的短脉冲。
- 斜向、断续、短时的能量压缩释放。

任何远程 VFX 都必须保留角色动作方向和受击点可读性，不能变成大面积蓝白主光束。

#### 禁止绿色战斗服 / 紫色连体魔族组合

不得使用大面积绿色战斗服 + 紫色连体服 / 肌肉体块 / 魔族风披肩等组合。

如果需要冷色系对手或训练木桩，应使用冷铁蓝灰、暗红、低饱和黑紫、机械训练材质等原创拳馆语言，避免触发现成动漫角色联想。

#### 禁止经典敌我阵营色复刻

不得通过以下方式暗示现成 IP：

- 主角橙蓝，对手绿紫。
- 变身金发金焰，对手紫白冷光。
- 正派蓝白光束，对手红黑光球。
- 角色服装、能量颜色、发型轮廓和招式构图同时接近已有作品。

如果某个颜色组合单独看不明显，但与发型、服装、姿势、招式构图合在一起会产生强烈联想，也必须修改。

#### 原创替代方向

《星核斗魂》的颜色识别应建立在以下原创组合上：

- 深色拳馆环境：擂台蓝黑 + 冷铁蓝灰。
- 恒星训练能量：暗金待机灯 + 星核金 + 短帧金白核心。
- 身体冲击与风险：深红冲击。
- 系统学习反馈：冷青信号。
- 爆发规则：短时、局部、围绕拳脚和受击点，而不是长期变身外观。

最终判断标准：即使玩家看到截图，也应首先想到“原创星核拳馆格斗”，而不是任何现成动漫 IP、经典角色配色、经典变身形态或经典能量波构图。

## 5. Character Design Direction

### 5.1 角色设计总原则

《星核斗魂》的角色设计必须服务一句核心规则：**先让玩家读懂格斗，再让能量放大情绪。** 角色的拳脚距离、出招方向、防守状态、受击方向、硬直窗口必须在第一眼就能看清；星核能量只能强化这些信息，不能遮挡或替代这些信息。

角色设计优先级如下：

1. **动作剪影优先**  
   站姿、防御、突进、攻击、受击、爆气必须在黑白剪影下可分辨。即使移除颜色、光效和细节，玩家也应该能判断角色正在做什么。

2. **拳脚端点优先**  
   手、脚、护手、鞋底、膝部和肘部是战斗可读性的主要锚点。角色装备必须让这些端点更清楚，而不是被衣摆、特效、长发或装饰遮住。

3. **能量围绕动作组织**  
   星芒、光环、尾迹、冲击线必须跟随拳脚方向、受击点、防守面或爆气核心展开。禁止让能量形状独立抢戏，尤其禁止大面积覆盖角色身体或对手身体。

4. **中等英雄化比例**  
   角色应是街机格斗可读的中等头身：肩宽、腰收、四肢清楚、重心稳定。避免过度写实导致小尺寸看不清，也避免过度卡通导致打击感不足。

5. **拳馆训练者，而不是神话战士**  
   所有角色都应像来自“星核拳馆”的训练者、对练体或训练器材。服装、护具、发光节点、能量计量带都应有训练和实战功能感，而不是纯装饰。

6. **原创识别高于流行借鉴**  
   可以吸收“高速、热血、压迫感、爆发力”的情绪，但不能复刻或暗示任何现成动漫、游戏 IP 的人物轮廓、发型、服装、变身、招式姿势、标志或经典配色。

视觉层级固定为：

**身体动作形状 > 明暗剪影 > 拳脚端点 > 状态色块 > 局部星核能量 > 细节装饰**

当任何细节影响战斗可读性时，删除该细节。

### 5.2 MVP 玩家角色：均衡武斗家

MVP 玩家角色的视觉 archetype 是：

**“星核拳馆的均衡武斗家”**  
一个接受恒星能量训练的街机拳馆战士，动作扎实、装备轻量、能量克制，能够清楚展示拳、脚、防御、突进和爆气反杀。

#### 5.2.1 体型与比例

玩家角色体型应满足以下方向：

- **中等体块**：不能太瘦弱，也不能过度肌肉化。
- **宽肩窄腰**：形成清楚的倒三角上身，强化格斗姿态。
- **稳定下盘**：大腿、小腿和鞋底要有足够体积，让站姿和冲刺方向清楚。
- **手脚端点突出**：护手和鞋底可以略微放大，方便玩家读招。
- **头部不过大**：头部用于方向和表情识别，但不能抢过拳脚动作。
- **无夸张身体变形**：爆气时不改变骨架比例，不突然变高、变壮或改变发型体积。

推荐剪影特征：

- 头部：短发或中短发，轮廓干净。
- 肩部：一侧可有轻量护肩，形成轻微不对称识别点。
- 手部：护手体积清楚，是攻击方向的主视觉锚点。
- 腰部：星核能量计量带形成横向识别线。
- 脚部：训练鞋或护靴鞋底清楚，方便判断移动和落点。

#### 5.2.2 装备方向

玩家角色装备应像实战训练装备，而不是奇幻盔甲。

核心装备：

| 部位 | 设计方向 | 可读性目的 |
|---|---|---|
| 护手 | 轻量硬质护手，切角形，拳峰有小型星核节点 | 强化拳击方向和攻击端点 |
| 前臂 | 压缩护具或短护臂，避免复杂绑带 | 让防御姿态更清楚 |
| 肩部 | 单侧轻量护肩或短护甲片 | 提供原创识别点，但不能遮挡头部和手臂 |
| 胸腹 | 训练背心或贴身战斗训练服 | 保持躯干旋转和受击动作可读 |
| 腰部 | 星核能量计量带，中心或侧面有小型发光计量器 | 表示能量系统和角色身份 |
| 膝部 | 简洁护膝，避免太多层叠装饰 | 强化蹲防、起跳、踢击动作 |
| 脚部 | 厚底训练鞋或轻护靴 | 强化站位、突进和踢击落点 |

装备材质语言：

- 主要材质：哑光训练布料、压缩护具、冷铁蓝灰护甲。
- 次要材质：暗金金属边、磨损切角金属片。
- 能量材质：小面积星核金发光节点。
- 禁止材质：大面积发光盔甲、全身透明能量罩、复杂飘带、长披风、过多金属尖刺。

#### 5.2.3 服装方向

玩家角色服装应统一为“街机拳馆中的高能训练服”。

推荐组合：

- 上身：无袖或短袖训练背心，外层可有短款训练夹克或局部护甲。
- 下身：紧凑训练裤、压缩裤或短护甲训练裤。
- 手部：半指或封闭式护手。
- 脚部：硬底训练鞋。
- 腰部：星核能量计量带作为主识别装置。

服装形状应以硬边、切角、短线段为主，呼应 UI 的硬边矩形和切角语言。衣服不应有大面积飘动部件，因为 Web 2D sprite sheet 成本高，也容易遮挡攻击动作。

禁止方向：

- 禁止经典武道服、标志性战斗制服、强识别斗篷、长飘带。
- 禁止让服装主色形成已知 IP 的经典英雄配色组合。
- 禁止通过胸口大标志或背部大图案建立识别，因为小尺寸战斗视角下不可读，且容易产生 IP 联想。

#### 5.2.4 发型方向

玩家角色发型必须短、中短、干净、可控。

允许方向：

- 短碎发。
- 低体积短发。
- 轻微上扬但不尖刺化的运动发型。
- 短马尾或贴近头部的束发。
- 剃短侧边、顶部简洁的拳馆训练者发型。

禁止方向：

- 禁止高耸尖刺发。
- 禁止放射状大体积发型。
- 禁止爆气后头发变色、变长、竖起或变成金色火焰轮廓。
- 禁止任何能让玩家联想到现成动漫主角的发型轮廓。

发型在战斗视角下只承担两个功能：

1. 让玩家看清角色面朝方向。
2. 提供轻微个性，但不抢拳脚动作。

#### 5.2.5 能量节点方向

玩家角色的星核能量应来自“训练装备调压”，而不是天生超人变身。

推荐能量节点位置：

- 护手拳峰：攻击时短暂亮起。
- 前臂护具：防御和蓄力时出现细能量线。
- 腰部计量带：爆气、反击、能量状态的主节点。
- 脚踝或鞋底：突进、后撤、踢击时短暂闪光。
- 胸口可有很小的稳定灯，但不能成为大面积主视觉核心。

能量节点规则：

- 常态只允许低亮度暗金或微弱星核金。
- 攻击瞬间允许局部星核金 `#FFE76A`。
- 爆气峰值允许极短时间核心金白 `#FFF5C8`。
- 受击、危险、反击窗口可使用深红冲击 `#B93A46`，但必须局部。
- 功能提示可使用冷青信号 `#39D6C8`，但不能变成角色主配色。
- 能量节点必须小于身体主形状，不能变成全身持续光焰。

#### 5.2.6 色彩分配

玩家角色色彩必须保持“深色拳馆训练者 + 小面积恒星能量”的结构。

推荐比例：

| 色彩类型 | 推荐占比 | 用途 |
|---|---:|---|
| 擂台蓝黑 `#090D18` | 35–45% | 服装暗部、主体底色 |
| 冷铁蓝灰 `#263241` | 25–35% | 护具、裤装、阴影体块 |
| 暗金待机灯 `#C28A38` | 8–12% | 装备边线、计量带、待机节点 |
| 星核金 `#FFE76A` | 3–6% | 攻击瞬间、能量节点 |
| 核心金白 `#FFF5C8` | 1–3% | 爆气峰值、命中核心闪光 |
| 冷青信号 `#39D6C8` | 1–3% | 功能性提示、训练反馈 |
| 深红冲击 `#B93A46` | 状态限定 | 受击、危险、反击窗口 |

玩家角色不应使用高饱和大色块。高饱和颜色只允许出现在短时、局部、关键信息上。

#### 5.2.7 动作姿态方向

玩家角色动作必须体现“稳定拳脚 + 高速星核爆发”。

常态站姿：

- 侧向 2.5D 格斗站姿，身体略微面向镜头。
- 前手抬起，后手保护下颌或胸口。
- 重心下沉，膝盖微弯。
- 肩线和髋线有轻微扭转，显示随时可进攻。
- 星核腰带低亮度待机，不持续外放大光效。

移动姿态：

- 前进时上身略压低，脚步短促。
- 后撤时护手保持防御，不做夸张滑行。
- 冲刺时用斜向速度线和鞋底短闪表现速度，不用大面积残影。

攻击姿态：

- 轻攻击：直线清楚，拳脚端点突出，能量只在端点短闪。
- 重攻击：身体扭转更明显，肩、腰、脚形成清楚发力链。
- 突进攻击：身体方向、脚底推力、拳脚目标点必须一致。
- 能量攻击：仍然以拳脚命中点为核心，不能变成角色站立发射大范围光束。

防御姿态：

- 前臂形成明确防御面。
- 身体收紧，头部压低。
- 能量线贴近护手或前臂，不形成大面积圆盾遮挡角色。

爆气姿态：

- 先压缩身体，再短促爆开。
- 核心亮点来自腰带、护手、脚底。
- 爆气是“星核调压过载”，不是变身。
- 不改变发型、身体比例、服装轮廓或主配色。

### 5.3 训练木桩 / 训练靶设计方向

训练对象必须一眼看出“这是训练器材，不是真人敌人”。

训练木桩不应复刻传统武术木人桩，而应设计为：

**“星核拳馆复合训练桩”**  
由重型底座、竖向缓冲柱、可更换打击垫、能量反馈灯和计分感应板组成。

#### 5.3.1 剪影方向

训练对象剪影应明显区别于角色：

- 身体是竖向柱体或厚矩形结构。
- 底部有稳定底座，显示不可移动或低移动性。
- 可有短机械臂、侧向打击垫，但不能像真人手臂一样灵活。
- 顶部不能有真实头部、头发或脸。
- 不使用人类服装、人类表情或人类姿态。

推荐结构：

- 下方：厚重圆形或切角矩形底座。
- 中部：主缓冲柱，带分段护垫。
- 左右：短训练臂或可调节打击板。
- 正面：冷青命中区标记。
- 顶部：小型状态灯或传感器，不做成脸。

#### 5.3.2 色彩方向

训练对象应比角色更“器材化”。

推荐色彩：

- 主体：冷铁蓝灰 `#263241`。
- 暗部：擂台蓝黑 `#090D18`。
- 命中区：冷青信号 `#39D6C8`。
- 磨损边：低饱和暗金 `#C28A38`。
- 受击反馈：短促深红冲击 `#B93A46` 或星核金闪点。

训练对象不应大量使用玩家角色的星核金。星核金只用于命中确认或训练评分反馈，不能让训练靶看起来像可操作角色。

#### 5.3.3 动画与反馈

训练对象动画要简单、功能明确：

- 待机：轻微状态灯闪烁，主体不做呼吸动作。
- 受击：命中点短闪，局部凹陷或震动。
- 防御测试：打击垫短暂展开或亮起冷青边框。
- 破防测试：目标板从冷青转为短促深红，再恢复。
- 训练完成：顶部状态灯或正面计分板亮起暗金。

禁止：

- 禁止训练对象做出痛苦表情。
- 禁止训练对象像真人一样倒地、惨叫或夸张反击。
- 禁止大面积透明护盾。
- 禁止将训练对象设计成怪物、外星人或类人敌人。

训练对象的作用是帮助玩家学习“读招定胜负”，因此它的视觉反馈必须比它的个性更重要。

### 5.4 简单脚本 CPU / 镜像对手设计方向

MVP 的简单脚本 CPU 不需要完整新角色成本，但必须与玩家角色一眼区分。

推荐方向：

**“星核拳馆影练对手”**  
使用玩家角色的基础骨架和大部分动画，但通过头部模块、护具模块、色彩、边缘标记和状态灯形成清楚区别。

#### 5.4.1 成本控制原则

CPU 可以复用：

- 玩家角色骨架。
- 玩家角色基础站姿。
- 玩家角色移动动画。
- 玩家角色轻攻击、重攻击、防御、受击动画。
- 玩家角色基础爆气结构。

CPU 必须替换或调整：

- 头部轮廓。
- 脸部可读方式。
- 护手或肩部外形。
- 腰部计量带标记。
- 主色分配。
- 边缘状态灯。
- 攻击预警颜色和图形。

禁止只做简单换色。如果只换颜色，在高强度战斗和色弱情况下会混淆玩家与敌人。

#### 5.4.2 CPU 视觉特征

CPU 应更像训练系统生成的对练体，而不是完整主角。

推荐特征：

- 头部：简化护目面罩或训练头盔，减少表情。
- 发型：无明显发型，或压在头盔下，避免和玩家头发混淆。
- 肩部：与玩家相反的一侧有护肩，形成镜像识别。
- 护手：形状更封闭、更硬，拳峰可有红色预警线。
- 腰部：能量计量带更机械化，可有短条状态灯。
- 服装：更统一、更少个性化，像训练系统制服。
- 边缘：少量深红或紫红边缘警示，但不能成为大面积主色。

#### 5.4.3 CPU 色彩方向

CPU 配色应与玩家有清楚差异，但仍属于星核拳馆世界。

推荐比例：

| 色彩类型 | 用途 |
|---|---|
| 更深的蓝黑 | CPU 主体，使其更像影练对手 |
| 冷铁蓝灰 | 护具和身体块面 |
| 暗金 | 低亮度训练系统节点 |
| 深红冲击 | 攻击预警、受击反馈、危险状态 |
| 少量紫红边缘 | 区分敌方轮廓，但必须克制 |
| 冷青信号 | 仅用于训练系统反馈，不作为敌方主色 |

CPU 不应使用和玩家同等亮度、同等面积的星核金。玩家的星核金代表可操作主体和主角身份；CPU 的深红边缘代表危险和对抗状态。

#### 5.4.4 CPU 动作差异

CPU 可以复用玩家动作，但需要在关键 pose 上略微区别：

- 待机：更直、更冷、更机械，呼吸幅度小。
- 攻击预备：预警动作更明显，帮助玩家练习读招。
- 防御：更像系统化格挡，前臂角度更规整。
- 受击：反馈清楚但不夸张，避免玩家误以为是主角受击。
- 爆气：不使用玩家的暖金核心爆发，而使用更短、更硬的深红边缘过载。
- 失败：像训练投影或训练系统关闭，节点逐个熄灭。

CPU 的视觉目的不是成为完整反派，而是成为“可读、可练、可击败”的对练对象。

---

### 5.5 一眼分辨规则

玩家、敌人、训练对象、UI/调试对象必须通过多重线索区分。禁止只靠颜色区分。

| 类型 | 剪影 | 色彩 | 动作 | 能量 | 识别重点 |
|---|---|---|---|---|
| 玩家角色 | 完整人形，短发，中等体块，拳脚端点清楚 | 深蓝黑 + 冷铁蓝灰 + 小面积星核金 | 有呼吸、有格斗节奏、有明确发力链 | 暖金为主，爆气短促金白 | 可操作主体，最清楚、最稳定 |
| CPU / 镜像对手 | 人形但更封闭，面罩或头盔，护具位置不同 | 更暗主体 + 深红边缘警示 | 更机械、更规整，预备动作更明显 | 深红边缘过载，少用星核金 | 危险目标，可读但不抢主角 |
| 训练木桩 / 训练靶 | 非人形器材，底座明显，无头发无表情 | 冷铁蓝灰 + 冷青命中区 | 震动、弹回、灯光反馈 | 命中点短闪，不持续外放 | 学习对象，不是真敌人 |
| UI / 调试对象 | 平面矩形、切角框、虚线或标签 | 冷青、白、灰为主，必要时深红警告 | 屏幕空间或固定覆盖，不做角色动作 | 不使用角色式星核能量 | 功能信息，不属于战斗实体 |

#### 5.5.1 玩家识别

玩家角色必须是画面中最稳定、最容易追踪的角色。

玩家识别手段：

- 暖金小节点集中在护手、腰带和鞋底。
- 脸部或发型比 CPU 更有人味，但不过度复杂。
- 待机呼吸更自然。
- 攻击能量更干净、更短促。
- 爆气时中心亮点清楚，但不持续遮挡身体。

#### 5.5.2 敌人识别

敌人必须有危险感，但不能和玩家混淆。

敌人识别手段：

- 面罩、头盔或封闭头部模块。
- 更暗的身体主体。
- 深红边缘预警。
- 护肩或护手形状与玩家不同。
- 预备动作更硬、更规整。
- 受击反馈和玩家不同，避免误读。

#### 5.5.3 训练对象识别

训练对象必须不像活人。

训练对象识别手段：

- 有底座。
- 有命中区板。
- 有冷青训练灯。
- 不做呼吸。
- 不做表情。
- 不使用完整人形站姿。
- 不使用玩家或敌人的爆气结构。

#### 5.5.4 UI / 调试对象识别

UI 和调试对象必须永远像功能层，不像世界中的攻击特效。

UI/调试识别手段：

- 使用硬边矩形、切角、虚线、标签。
- 保持屏幕空间或清楚的 overlay 层级。
- 不使用大面积星核金爆裂。
- 不模仿拳脚尾迹。
- 不使用角色轮廓或角色姿态。
- 关键调试框必须有形状和文字辅助，不能只靠颜色。

---

### 5.6 Expression / Pose Style

角色表情和 pose 风格应体现“热血但克制、爆发但可读”。

#### 5.6.1 表情风格

战斗视角下，表情不是主要信息来源。表情只能辅助角色状态，不能承载关键 gameplay 信息。

玩家表情方向：

- 常态：专注、冷静、略带紧张感。
- 攻击：咬牙、眉头压低。
- 受击：短暂痛感，但不夸张变形。
- 爆气：强压迫感，眼神集中，不做疯狂表情。
- 胜利：松一口气、拳头下压、暖色余温。
- 失败：低头、肩膀垂落、能量熄灭。

CPU 表情方向：

- 尽量无表情。
- 用面罩灯、边缘警示、姿态变化表达状态。
- 不做强人格反应，避免增加新角色成本。

训练对象表情方向：

- 无脸。
- 无眼睛。
- 无嘴。
- 只用灯、面板和机械反馈表达状态。

#### 5.6.2 站姿

玩家站姿必须形成清楚的格斗三角形：

- 双脚分开，前后脚有层次。
- 膝盖微弯。
- 前手可试探，后手保护。
- 头部朝向对手。
- 躯干略微侧身，减少被击面积。
- 腰部星核计量带在待机时低亮。

站姿不能太松散，也不能像超级英雄摆拍。站姿应该看起来随时能出拳、格挡、突进或后撤。

#### 5.6.3 攻击 pose

攻击 pose 必须遵守“预备、释放、命中、收招”四段可读逻辑。

- **预备**：肩、腰、腿出现明显蓄力方向。
- **释放**：拳脚端点成为画面主焦点。
- **命中**：能量集中在接触点，而不是角色全身。
- **收招**：身体露出短暂硬直，让玩家能读懂风险。

轻攻击：

- 动作短。
- 能量少。
- 端点清楚。
- 不产生复杂尾迹。

重攻击：

- 动作幅度更大。
- 身体扭转更明显。
- 星核金可在拳脚端点形成短弧。
- 收招 pose 必须清楚。

能量攻击：

- 必须从拳、脚、肘、膝或近身打击点产生。
- 可以有短距离冲击波或星芒爆点。
- 禁止变成大面积远程光束主视觉。
- 禁止用光效遮住身体发力过程。

#### 5.6.4 防御 pose

防御必须一眼看出“正在挡”。

推荐方向：

- 前臂在身体前形成明确防御面。
- 肩膀收紧。
- 头部压低。
- 腿部重心下沉。
- 护手边缘可出现短冷光或暗金线。
- 防御成功时，在接触点出现短促星芒或硬边冲击片。

禁止方向：

- 禁止用大圆盾完全遮住角色。
- 禁止用持续光罩代替防御姿势。
- 禁止防御 pose 和普通待机过于接近。

#### 5.6.5 受击 pose

受击 pose 必须清楚表达攻击方向和硬直。

推荐方向：

- 受击点出现短促深红冲击。
- 身体朝受击方向反折或压缩。
- 头肩出现方向性偏移。
- 手脚不要完全糊成一团，仍需保留身体结构。
- 重击受击可以有更明显的弯腰、后仰或滑步。

受击表现不能依赖大面积血液或复杂伤痕。《星核斗魂》的受击语言应是冲击、硬直、能量短路，而不是血腥表现。

#### 5.6.6 爆气 pose

爆气是“短促恒星爆裂”，不是持续变身。

爆气 pose 结构：

1. 身体压低，拳头或脚底靠近重心。
2. 腰部星核计量带亮起。
3. 护手、脚底、肩部节点依次点亮。
4. 金白核心在极短时间爆闪。
5. 深红或紫红边缘只出现在爆裂边缘。
6. 光效迅速回收，角色重新进入可读战斗姿态。

爆气禁止：

- 禁止头发变色或竖起。
- 禁止全身长时间金色火焰包裹。
- 禁止体型变化。
- 禁止持续大面积透明 aura。
- 禁止让爆气遮住对手和场地边界。
- 禁止让爆气特效比攻击、防御、受击信息更重要。

#### 5.6.7 胜利 pose

胜利 pose 应是热血后的余温，而不是过度炫耀。

推荐方向：

- 角色站稳，拳头下压或护手收回。
- 身上残留少量暗金余光。
- 呼吸放慢。
- 腰部星核计量带从高亮回到待机。
- 可以有一小段星芒散落，但必须局部、短时。

胜利画面色彩应偏暖，但不应变成全屏金光。

#### 5.6.8 失败 pose

失败 pose 应传达“能量熄灭、训练中断、身体失衡”。

推荐方向：

- 肩膀下垂。
- 膝盖弯曲或单膝触地。
- 护手垂下。
- 星核节点逐个熄灭。
- 冷阴影变重。
- 不使用夸张昏迷符号或喜剧化表情。

失败不是血腥毁灭，而是战斗节奏被读穿、能量系统被压制。

### 5.7 LOD / Camera Distance Philosophy

《星核斗魂》面向 Godot Web 2D Canvas 和 2.5D 横向战斗视角，因此角色必须在小尺寸、快速运动、浏览器性能限制下保持清楚。

角色设计必须通过以下测试：

1. **黑白剪影测试**：移除颜色后，站姿、防御、攻击、受击、爆气仍可分辨。
2. **缩小测试**：缩到战斗实际显示尺寸后，拳脚方向仍清楚。
3. **灰度测试**：移除色相后，玩家、CPU、训练靶仍能靠明度和形状区分。
4. **一帧测试**：随机截取攻击帧，仍能判断攻击方向。
5. **特效关闭测试**：关闭 VFX 后，动作仍然成立。
6. **色弱安全测试**：不依赖红、金、青的颜色差异作为唯一信息。

#### 5.7.1 战斗距离下必须保留的细节

必须保留：

- 头部朝向。
- 肩线和髋线方向。
- 前后脚站位。
- 拳脚端点。
- 护手轮廓。
- 鞋底轮廓。
- 腰部星核计量带大形状。
- 玩家与 CPU 的头部差异。
- 攻击、防御、受击的主 pose。
- 命中点和防御面的短时反馈。

这些细节直接影响“读招定胜负”，不能删除。

#### 5.7.2 战斗距离下应删除的细节

应删除或极度简化：

- 细小文字。
- 微型徽章。
- 复杂纹身。
- 多层绑带。
- 细碎布料花纹。
- 小饰品、项链、耳饰。
- 过细发丝。
- 复杂鞋带。
- 大量衣服褶皱。
- 多层透明材质。
- 持续发光边线。
- 需要近景才能看懂的装备结构。

如果一个细节在战斗距离下看不清，它就不应占用 sprite sheet 成本。

#### 5.7.3 小 sprite sheet 规则

角色 sprite sheet 必须优先覆盖 gameplay 状态，而不是展示复杂表演。

MVP 玩家角色优先动画：

1. Idle / 待机。
2. Walk / 前后移动。
3. Dash / 突进或快速步。
4. Light Attack / 轻攻击。
5. Heavy Attack / 重攻击。
6. Guard / 防御。
7. Hit React / 受击。
8. Knockdown or Stagger / 击退或硬直。
9. Burst / 爆气。
10. Win / 胜利。
11. Lose / 失败。

每个动画都应保持：

- 同一角色比例。
- 同一脚底基准线。
- 同一镜头角度。
- 同一光源方向。
- 同一线条粗细感。
- 同一材质语言。
- 同一色彩 token。
- 同一能量节点位置。

禁止为了单个酷炫动作改变角色比例、服装结构或发型体积。

#### 5.7.4 generate2dsprite 一致性规则

使用 `.claude/skills/generate2dsprite` 生成角色资产时，所有角色相关提示必须保持以下一致性：

- 描述为原创角色，不能引用现成 IP 名称或角色名。
- 明确 Godot 2D Canvas、2.5D side-view fighting game、Web-readable sprite。
- 明确中等体块、短或中短发、宽肩窄腰、拳脚端点清楚。
- 明确服装为星核拳馆训练装备，而非经典动漫战斗服。
- 明确主色为深蓝黑、冷铁蓝灰，小面积暗金和星核金。
- 明确能量只在护手、脚底、腰带等节点局部出现。
- 明确禁止大面积 aura、持续透明光效、复杂粒子。
- 明确禁止尖刺发型、金发变身、经典能量波姿势、已知 IP 配色。
- 同一角色的不同动作必须复用同一装备、同一发型、同一比例。
- 大型 VFX 应尽量拆成独立 VFX sheet，不直接画死在角色主体帧里。

角色生成时应优先要求：

**clean silhouette, readable limbs, clear fighting pose, small localized starcore energy, matte training gear, cut-corner guards, no recognizable existing IP influence**

#### 5.7.5 VFX 与角色分离原则

角色 sprite 本体只保留必要的局部能量亮点。较大的星芒、冲击波、命中爆点、速度线应尽量作为独立 VFX 资产处理。

原因：

- 便于复用。
- 降低 sprite sheet 体积。
- 避免每个角色动作都携带大面积透明像素。
- 便于在 Godot Web 中控制性能。
- 便于根据 gameplay 状态开关特效。
- 保证关闭特效后角色动作仍可读。

### 5.8 IP Safety

《星核斗魂》必须保持原创视觉身份。角色设计不能复刻、暗示或组合任何现成动漫、游戏、漫画、影视 IP 的可识别元素。

#### 5.8.1 明确禁止

禁止以下方向：

- 禁止复刻现成角色的脸型、发型、身体比例、服装结构或标志物。
- 禁止使用高耸尖刺发型、放射状头发轮廓或爆气后发型变形。
- 禁止金发、金焰、全身金色 aura 的变身视觉。
- 禁止橙蓝主角式经典配色组合。
- 禁止蓝白大型双手能量波作为主视觉构图。
- 禁止绿色战斗服加紫色连体服等强绑定阵营配色组合。
- 禁止使用可识别的战斗盔甲轮廓、肩甲结构或身体护甲组合。
- 禁止使用现成 IP 的手势、蓄力姿势、合体姿势、变身姿势、胜利姿势。
- 禁止使用现成 IP 的符号、文字、徽章、道具、尾巴、头环、探测器类装置。
- 禁止在 prompt、文件名、注释或设计说明中引用现成 IP 角色作为视觉目标。
- 禁止“像某某角色但换颜色”的设计方法。
- 禁止“把多个知名角色元素混合一下”的设计方法。

只要观众能在一眼内联想到某个现成 IP 角色，该设计就不合格。

#### 5.8.2 原创替代方向

当需要表现“热血、高速、能量、反杀”时，使用以下原创方向替代：

| 需求 | 禁止方向 | 原创替代方向 |
|---|---|---|
| 强者气场 | 全身持续金焰 aura | 腰带、护手、脚底短促星核调压闪光 |
| 高速突进 | 大面积残影拖满屏幕 | 鞋底短闪、斜向速度线、身体压低 |
| 能量攻击 | 双手前推大型蓝白光束 | 拳脚命中点爆裂、短距离星芒冲击、半圆轨道切线 |
| 变强状态 | 发色改变、头发竖起、体型变化 | 装备节点过载、计量带亮度提升、姿态更压迫 |
| 主角识别 | 经典橙蓝英雄配色 | 深蓝黑训练服 + 冷铁蓝灰护具 + 小面积星核金 |
| 敌人识别 | 经典绿紫魔族组合 | 深色影练制服 + 深红边缘预警 + 面罩模块 |
| 神秘科技 | 现成探测器或标志道具 | 星核拳馆计量带、护手调压器、训练系统灯条 |
| 夸张发型 | 尖刺、放射、变色 | 短发、中短发、贴头束发、低体积运动发型 |

#### 5.8.3 星核拳馆原创锚点

所有角色设计都应回到以下原创锚点：

- 街机拳馆。
- 恒星能量训练。
- 硬边切角护具。
- 小面积星核节点。
- 腰部能量计量带。
- 拳脚端点发光。
- 半圆能量轨道。
- 局部短促爆裂。
- 暖侧光与冷阴影。
- 可读的格斗 pose。

只要设计偏离这些锚点，开始依赖“经典动漫超人感”“大能量光束”“发型变身”“知名配色记忆”，就必须回退。

《星核斗魂》的角色应该让玩家记住的是：**拳脚读招、星核爆点、拳馆训练者的原创能量格斗感**。

## 6. Environment Design Language

### 6.1 环境设计总原则

《星核斗魂》的环境设计必须服务于一个优先级：**让玩家清楚读懂战斗，再让场景强化“星核拳馆”的身份与热血情绪。**

环境不是主角，角色、HUD、打击反馈、能量状态才是玩家需要第一时间读取的信息。因此所有地图、背景、道具、灯光、纹理和动画都必须遵守以下原则：

1. **战斗读取优先**
   - 玩家必须能快速看清角色站位、拳脚距离、出招方向、防守状态、命中区、硬直窗口、爆气、受击、反击等关键状态。
   - 背景不得抢走角色剪影、攻击轨迹和 HUD 信息的视觉焦点。

2. **背景后退，角色前进**
   - 环境整体应使用低对比、低饱和、低细节密度的视觉处理。
   - 角色、VFX、HUD 使用更明确的对比和更清晰的轮廓。
   - 背景亮度不得接近角色高光和能量特效亮度。

3. **星核拳馆统一一切**
   - 所有场景都应看起来属于同一个训练机构，而不是零散的奇幻竞技场。
   - 环境关键词：街机拳馆、恒星能量训练、冷铁蓝灰结构、暗金待机灯、星核圆环、训练标线、功能性设备、可控、硬派、可学习。

4. **拳脚先于能量**
   - 环境中的能量装置、发光圆环、训练灯带只能辅助氛围，不能形成大面积视觉噪声。
   - 能量光效应短时、局部、低频出现。
   - 常态地图不应像霓虹舞台，也不应像魔法空间。

5. **功能感高于装饰感**
   - 每一个环境元素都应有明确用途：地面标线帮助判断距离；擂台边界帮助判断空间限制；冷青命中区暗示训练系统；星核圆环暗示能量来源；墙面设备暗示拳馆科技与训练文化。
   - 不添加纯装饰性、难以解释、会干扰读招的复杂元素。

6. **Web 60fps 友好**
   - 地图必须适合 Godot 2D Canvas + 2.5D presentation。
   - 不依赖复杂实时光照、重粒子、过多透明叠加、复杂滚动层或高频背景动画。
   - 背景应优先使用静态或近静态分层图像，少量可控动画只用于氛围点缀。

### 6.2 核心场景：星核拳馆 / 训练擂台

#### 建筑风格

星核拳馆是《星核斗魂》MVP 的核心环境。它不是传统武馆，也不是纯科幻实验室，而是两者之间的原创混合体：

> **一个为恒星能量格斗者设计的地下街机拳馆。**

建筑风格应体现：

- **拳馆基础**：矩形擂台、厚重地垫、训练标线、沙袋、打击桩、护具架、计时屏、金属梁架、灯架、墙面结构框架。
- **星核训练系统**：中央压低亮度的星核圆环、地面嵌入式能量导线、墙面恒星核心稳定器、冷青色状态指示灯、暗金待机灯、低亮度能量监测屏。
- **街机感**：局部几何灯带、清楚的对战区域、可辨识的训练设备、横向舞台构图；但不使用夸张霓虹、不堆满广告牌、不做过度娱乐化装饰。

#### 文化 / 历史暗示

环境应通过视觉细节暗示星核拳馆的历史，而不是靠文字说明。

可使用的暗示：

- 墙面上有旧训练标线、磨损痕迹、补强钢板，说明这里经历过长期高强度训练。
- 地面中心的星核圆环有轻微灼痕和修补痕迹，暗示能量爆发曾多次发生。
- 角落摆放不同规格的护手、护腿、破损垫片，暗示拳馆有系统化训练传统。
- 训练木桩底座周围有冲击划痕，暗示新人反复练习“读招定胜负”。
- 墙面设备不应像军工实验室，而应像拳馆自行改造的训练系统：实用、粗粝、可靠。

避免：大量文字说明、复杂徽章、家族纹章或宗教符号、现成 IP 的标志性建筑、过度宏大的宇宙神殿感、过度赛博朋克酒吧感。

#### 空间布局

星核拳馆 / 训练擂台应采用清晰的横向战斗布局：

1. **中心战斗区**
   - 玩家与敌人主要活动区域。
   - 地面细节最低，颜色最克制。
   - 必须保证角色脚底、腿部、攻击端点清楚可读。

2. **左右边界区**
   - 用擂台边框、墙面缓冲垫、地面边线或能量边界装置提示可移动范围。
   - 边界必须清楚，但不能过亮。
   - 边界元素应低于角色与攻击 VFX 的视觉优先级。

3. **后方拳馆身份层**
   - 放置训练器材、结构柱、墙面屏幕、星核设备。
   - 细节可比战斗区略多，但必须降低对比。
   - 不得在角色身后放置高亮圆形、强对比线条或复杂剪影，避免破坏角色轮廓。

4. **远景氛围层**
   - 可见暗金灯带、冷铁蓝灰墙体、低亮星核核心装置。
   - 远景应更暗、更模糊、更低饱和。
   - 远景动画极少，只做轻微呼吸灯或缓慢能量脉冲。

### 6.3 2.5D 战斗空间规则

《星核斗魂》采用 Godot 2D Canvas + 2.5D presentation。环境应看起来有空间深度，但实际读取必须像清晰的横向格斗游戏。

#### 前景规则

前景元素必须极少使用。

允许：很低、很暗的擂台边缘；不遮挡角色脚部的地面前沿；极少量低透明度的环境遮罩；胜利或失败状态下短时出现的前景光晕。

禁止：遮挡角色身体的前景栏杆、柱子、观众、布条；大面积前景烟雾；高亮前景粒子；高频移动前景物；会覆盖攻击轨迹的装饰。

前景的作用只能是增加舞台深度，不得影响读招。

#### 中景规则

中景是最重要的战斗读取层，包括角色、训练木桩 / CPU、攻击 VFX、受击反馈、防守反馈、地面接触阴影、距离标线、擂台边界提示。

中景必须拥有最高的清晰度和最稳定的视觉层级。背景中的任何元素都不能与中景争夺注意力。

#### 背景规则

背景应分为两层：

1. **拳馆身份层**：墙面结构、训练设备、能量监测屏、灯架、护具架、星核稳定器。
2. **星核氛围层**：低亮度星核圆环、暗金待机光、冷青状态灯、深蓝黑空间深度、低频能量脉冲。

背景必须低对比、低饱和、低动态，不出现密集高亮线条，不在角色背后形成强烈轮廓干扰，不使用大面积白光、金光或红光。

#### 地面标线规则

地面标线是环境设计的重要功能元素，必须帮助玩家判断距离，而不是变成装饰噪声。

推荐标线：横向距离刻度线、中央星核圆环、左右站位参考线、训练区边界线、冷青色命中校准线、低亮度擂台框线。

标线规则：

- 标线亮度必须低于角色轮廓亮度。
- 标线颜色以冷铁蓝灰、暗金、低亮冷青为主。
- 中央星核圆环可以存在，但应压低亮度，避免抢夺角色脚底信息。
- 标线宽度要稳定，不做复杂花纹。
- 战斗区域内的纹理和标线不得密到影响脚步判断。

#### 角色脚底阴影规则

脚底接触阴影是 2.5D 可读性的核心。

必须保证：

- 每个角色脚下都有清晰、稳定、低透明度的接触阴影。
- 阴影颜色偏深蓝黑或冷灰，不使用纯黑硬块。
- 阴影形状应简洁，随角色姿态略微变化即可，不做复杂实时变形。
- 角色跳跃、后撤、冲刺时，阴影应帮助玩家判断落点和距离。
- 地面不能过暗到吞掉脚底阴影，也不能过亮到让阴影失效。

避免：地面高亮纹理穿过脚底、角色脚下有高对比装饰圆环、阴影与地面标线混在一起、大面积能量光覆盖脚底。

#### 边界可读性规则

战斗边界必须清楚，但不能像 HUD 一样抢眼。

可使用：擂台边线、低矮护栏、地面边界灯、墙面缓冲垫、两侧训练设备形成的视觉收口、暗金或冷青低亮提示。

禁止：高亮闪烁边界、复杂机械门、大面积发光墙、与攻击 VFX 同色同亮度的边界效果、会误导玩家以为可以互动的复杂装置。

### 6.4 Texture Philosophy

《星核斗魂》的环境纹理采用：

> **手绘感、风格化、非 PBR、低噪声、低细节密度。**

#### 手绘 / 风格化

环境纹理应有明确的美术控制，而不是追求真实照片质感。

推荐：手绘边缘磨损、简化金属块面、稍微夸张的光影分区、清楚的材质大形、可控的颜色分组、适度的笔触感。

避免：照片贴图、真实脏污过多、高频噪点、复杂材质扫描感、真实反射、真实粗糙度、真实 PBR 金属流程。

#### 非 PBR

本项目的环境不追求真实物理材质。原因：

- Godot 2D Canvas + Web 目标更适合轻量化贴图表现。
- PBR 细节会增加视觉噪声，降低读招清晰度。
- 真实高光可能与能量特效、受击闪光、HUD 提示冲突。
- 风格化材质更容易保持角色、UI、VFX 的统一视觉语言。

材质应通过颜色、明暗块面和简化高光表达，而不是通过复杂法线、粗糙度、金属度表达。

#### 低噪声

地面、墙面、设备纹理必须控制噪声。

推荐：大块面、低对比磨损、稀疏划痕、明确方向的结构线、少量边缘旧化、颜色变化控制在同一色相范围内。

禁止：密集刮痕、颗粒噪点铺满、高对比裂纹、大量小字、小图标、小贴纸、与角色轮廓接近的复杂背景线条。

#### 低细节密度

战斗区域的细节密度最低，远离角色的位置可以略高。

细节密度分级：

1. **角色站位区：最低细节**：地面简洁；标线清楚；无高频纹理；无复杂发光图案。
2. **擂台边缘区：低细节**：可有边缘磨损、低亮边线、少量结构铆钉。
3. **背景设备区：中低细节**：可有训练器材、能量屏、护具架，但全部降低对比。
4. **远景氛围区：最低对比**：可以有形状，不强调细节，只提供深度和世界观氛围。

这种纹理哲学适合 Web 和读招，因为它减少 GPU 压力、降低文件体积、减少透明叠加需求，同时让玩家更容易识别角色动作和关键反馈。

### 6.5 Prop Density Rules

道具密度必须根据游戏状态变化。道具不是越多越好，而是要服务当前玩家注意力。

#### 训练模式

- **道具密度**：低
- **环境目标**：清醒、干净、可学习。
- **允许**：训练木桩、简单护具架、低亮状态屏、少量地面校准线、墙面训练计时器、左右边界提示装置。
- **禁止**：大量杂物、高亮广告牌、大量观众剪影、多个发光设备同时闪烁、飘动物、烟雾、纸片、火花等持续动态元素。

#### 普通战斗

- **道具密度**：中低
- **环境目标**：暖侧光 + 冷阴影，高对比、硬派、可控。
- **允许增加**：更多墙面灯架、低亮星核稳定器、背景训练设备、冷铁蓝灰结构柱、暗金侧光、少量损耗痕迹。
- **仍然禁止**：背景过亮、复杂滚动层、大面积发光装饰、密集运动物体、大量透明粒子。

#### 菜单背景

- **道具密度**：中
- **环境目标**：夜间拳馆开灯前的期待。
- **允许**：深蓝黑拳馆全景、暗金待机灯、星核圆环低亮休眠、训练器材剪影、局部能量设备待机光、更强的空间纵深。
- **限制**：不使用大面积闪烁；不使用过亮霓虹；不让背景比菜单按钮更抢眼；菜单 UI 区域背后必须保持低细节、低对比。

#### 胜利状态

- **道具密度**：中低
- **环境目标**：暖色余温，强调角色完成训练或战斗后的掌控感。
- **允许**：星核圆环短暂升亮、暗金灯带增强、地面低亮能量余波、背景设备显示稳定状态、胜利角色背后柔和暖色轮廓。
- **禁止**：全屏金白光、大量烟花式粒子、过亮背景遮住胜利姿态、复杂动态道具抢走角色动作。

#### 失败状态

- **道具密度**：低
- **环境目标**：冷暗熄灭，让玩家理解失败，但保持界面和角色状态可读。
- **表现方式**：暗金灯降低、冷铁蓝灰阴影变重、星核圆环降为极低亮度、冷青状态灯少量闪烁、地面标线保留但更暗。
- **禁止**：大量红色警报、过度故障火花、全屏黑雾、复杂破坏效果。

### 6.6 Environmental Storytelling Guidelines

环境叙事必须通过视觉结构和道具逻辑完成，不依赖大段文本。

#### 讲述“星核拳馆”

星核拳馆应被表现为一个真实存在、长期运作的训练场所。

可使用：磨损地垫、反复维修的擂台边框、被打凹的缓冲垫、护手和护腿收纳架、训练木桩底座划痕、墙面旧式计时器与新式能量屏并存、冷铁蓝灰金属结构与暗金灯带组合。

视觉信息应传达：这里不是一次性比赛场，而是战士每天训练、对练、失败、再站起来的地方。

#### 讲述“训练系统”

训练系统应看起来可操作、可测量、可反复使用。

可使用：地面距离刻度、冷青命中校准线、墙面训练回放屏、可更换打击垫、训练木桩上的命中区、能量输出稳定器、简洁状态灯。

避免：不明所以的科幻装置、装饰性过强但没有训练用途的巨大机器、看起来像实验室囚笼或军事审讯室的环境语言。

训练系统的核心叙事是：星核拳馆相信“读招定胜负”，所以空间本身就是教学工具。

#### 讲述“能量来源”

星核能量应被表现为可控的训练能源，而不是神秘魔法或失控宇宙力量。

可使用：中央低亮星核圆环、墙面稳定器、地面能量导线、暗金待机灯、核心金白短时出现、冷青状态灯表示系统监控。

常态下，星核能量应该“被压住”。只有爆气、反杀、胜利余温等状态才短促升高亮度。

避免：整个场景一直强烈燃烧、大面积宇宙星云背景、神殿式能量祭坛、失控爆炸常态化、持续漂浮的发光石块。

#### 讲述“对练文化”

拳馆应传达公平、硬派、重视练习的对练文化。

可使用：左右对称或近似对称的擂台布局、清晰起始站位、墙面不同等级的护具、训练木桩和影练对手共用同一套拳馆设备、旧伤痕和修补痕迹、低调胜负记录屏。

环境应表达：胜负来自观察、判断和执行，而不是场景混乱或视觉欺骗。

### 6.7 generate2dmap / codex-gateway-imagegen 生成规则

地图生产采用两层流程：

1. 使用 `.claude/skills/generate2dmap` 组织地图需求、布局、图层、风格约束和可用输出。
2. 使用 `.claude/skills/codex-gateway-imagegen` 作为具体游戏生图入口，生成地图、背景、场景参考图或需要视觉验证的环境资产。

`generate2dmap` 负责“地图该是什么”，`codex-gateway-imagegen` 负责“把已约束好的地图视觉生成出来”。不得绕过 Art Bible 直接用泛化提示词生成地图。

#### 地图 prompt 必须包含

1. **项目身份**：原创 2.5D Web 格斗游戏；星核拳馆；街机拳馆中的恒星能量训练者；横向对战舞台；读招清晰优先。
2. **场景类型**：星核拳馆训练擂台；室内训练场；冷铁蓝灰金属结构；深蓝黑地面；暗金待机灯；低亮星核圆环；地面训练标线。
3. **构图要求**：横向格斗游戏视角；2.5D presentation；中央战斗区域干净；背景后退；角色站位区低细节；左右边界清晰；地面脚底阴影可读；背景设备低对比。
4. **色彩要求**：擂台蓝黑 `#090D18`；冷铁蓝灰 `#263241`；暗金待机灯 `#C28A38`；星核金 `#FFE76A` 只做局部；核心金白 `#FFF5C8` 只用于短时高能状态；冷青信号 `#39D6C8` 只用于训练指示；深红冲击 `#B93A46` 不作为常态环境主色。
5. **纹理要求**：手绘风格化；非 PBR；低噪声；低细节密度；大块面；简化金属材质；清晰地面标线；不使用照片质感。
6. **性能要求**：Web 60fps 友好；静态背景为主；少量低频灯光动画；不使用重粒子；不使用复杂透明叠加；不使用多层高速视差；不使用大面积发光雾。
7. **读招要求**：背景低对比；不抢角色剪影；不抢 HUD；不抢攻击 VFX；地面清楚；脚底阴影清楚；边界清楚；中央战斗区无杂物。

#### 地图 prompt 应避免 / 禁止包含

禁止描述：七龙珠式场景、天下第一武道会式竞技场、荒野岩山战场、精神时光屋式纯白无限空间、经典动漫武斗大会、现成 IP 风格、大型观众席、宏大古代擂台、浮空岛竞技场、神殿战斗场、赛博霓虹街头、过亮霓虹拳馆、宇宙星云背景、大面积爆炸光效、漫天粒子、高复杂机械背景。

禁止视觉倾向：背景比角色亮、地面花纹太密、中央战斗区有障碍物、强透视导致距离判断困难、多层前景遮挡、高饱和色铺满、大量红色常亮、全屏金白光、真实照片质感、PBR 金属反射、复杂实时光照暗示。

#### 与角色、UI、VFX 的一致性

地图生成后必须检查：

1. **角色一致性**
   - 玩家角色的冷铁蓝灰护具、星核腰带、拳脚端点必须在背景前清楚可见。
   - 影练 CPU 的深红边缘预警不能与背景红光混淆。
   - 训练木桩的冷青命中区不能被背景冷青灯带抢走。

2. **UI 一致性**
   - HUD 区域背后不能有高亮复杂背景。
   - 顶部血条、能量条、计时信息必须拥有干净背景。
   - 菜单按钮区域不能放在高对比器材或强光后面。

3. **VFX 一致性**
   - 星核金、核心金白只应在角色能量和关键反馈中最亮。
   - 环境常态星核圆环必须低亮，不能比技能特效更亮。
   - 深红冲击色主要服务受击、危险和 CPU 预警，不应成为环境常态主色。
   - 冷青主要服务训练反馈、命中区和系统提示，不应铺满背景。

4. **层级一致性**
   - 战斗读取层最高；拳馆身份层第二；星核氛围层第三。
   - 任何生成结果如果违反该层级，都必须返工或降噪处理。

### 6.8 Performance / Readability Constraints

《星核斗魂》目标平台为 Web / Browser，目标帧率为 60fps。环境必须从设计阶段就限制复杂度。

#### 背景动画限制

允许：暗金灯带极低频呼吸、冷青状态灯轻微闪烁、星核圆环缓慢低亮脉冲、背景屏幕少量循环扫描线、胜利 / 失败状态下短时亮度变化。

禁止：大面积循环动画、高频闪烁、大量机械结构运动、背景角色或观众持续运动、会吸引视线的强动态元素、战斗中持续变色的背景。

背景动画原则：**如果玩家会忍不住看背景动画，就说明它太强了。**

#### 光效限制

允许：局部暗金待机光、低亮冷青信号光、关键状态下短促星核金、胜利状态的柔和暖色余温、失败状态的冷暗熄灭。

禁止：大面积 Bloom 感、全屏泛光、持续金白核心光、多个高亮光源同时存在、背景光效与攻击 VFX 同亮度、长时间深红警报光。

光效原则：**环境可以发光，但不能比攻击、防守、受击和爆气更重要。**

#### 透明层限制

Web 目标下应避免大面积透明叠加。

限制：大面积半透明雾层禁止常态使用；多层半透明光晕禁止叠加过多；透明粒子禁止覆盖战斗区；前景透明遮罩仅可极低透明度、极小面积使用。

推荐替代：使用不透明或半透明较少的手绘光斑；使用静态贴图表达氛围；使用局部小范围发光点；用颜色块面而不是叠层特效表达光照。

#### 视差限制

2.5D presentation 可以使用轻微视差，但必须克制。

允许：远景极轻微移动、菜单背景轻微镜头漂移、非战斗状态下微弱空间层次、战斗中几乎静止的背景层。

禁止：多层高速视差、角色移动时背景明显滑动、强透视深度变化、会影响距离判断的地面位移、让玩家误判角色前后位置的视觉运动。

视差原则：**视差只服务深度感，不服务炫技。**

#### 粒子限制

环境粒子必须极少。

允许：菜单背景中极少量低亮尘埃、胜利状态短时暖色余光粒、爆气后残留极短时间的局部能量碎光、背景设备偶发低亮火花。

禁止：常态漂浮大量粒子、战斗区持续粒子雨、大面积烟雾、高亮能量粉尘、粒子穿过角色身体、粒子颜色与攻击命中反馈混淆。

粒子原则：**粒子只能是状态余韵，不能成为环境常态。**

#### 文件与层级复杂度限制

地图资产应优先保持：少层数、少透明、少动画、少高分辨率碎片、少独立发光元素、清晰分组、易于 Godot 导入与压缩。

推荐分层：

1. 地面基础层。
2. 地面标线层。
3. 背景结构层。
4. 背景设备层。
5. 低亮氛围光层。
6. 可选状态变化层。

不推荐：十几层以上复杂背景；每个灯都单独动画；多个全屏透明覆盖层；把战斗区装饰拆成大量小图块；使用超大尺寸无压缩背景图。

### 6.9 IP Safety

《星核斗魂》必须保持原创视觉身份。环境设计不能复刻、暗示或依赖任何现成 IP 的标志性场景。

#### 禁止方向

环境不得复刻或明显联想到：天下第一武道会式竞技场、龙珠式荒野岩山战场、精神时光屋式纯白无限空间、经典动漫武斗大会场地、圆形露天武术大会擂台、大型观众席环绕的传统比武场、沙漠岩柱、荒野裂谷、孤立石林作为主战场、巨大白色无边训练空间、现成动漫中高度可识别的擂台/神殿/宫殿/竞技场构图。

也不得使用近似现成 IP 的建筑轮廓、地面图案、背景山体组合、比赛装饰、文化符号、标志或色彩组合。

#### 原创替代方向

当需要“热血武斗场”时，使用以下原创方向替代：

1. **星核拳馆训练擂台**：室内、冷铁蓝灰结构、暗金待机灯、地面训练标线、中央低亮星核圆环、功能性训练设备。
2. **地下能量拳馆**：类似改造训练基地，有拳馆生活痕迹，有能量稳定系统，不像官方竞技大会，也不像传统武道会。
3. **恒星校准训练室**：更干净、更偏训练，冷青校准线更多，适合教程和训练模式，但避免纯白无限空间。
4. **旧拳馆升级区**：传统拳馆设施与星核设备混合，旧地垫、护具架、打击桩、新增能量导线、稳定器、状态屏。
5. **夜间待机拳馆**：适合主菜单，深蓝黑空间，暗金灯未完全开启，星核圆环低亮休眠，强调期待感而不是比赛场面。

#### 安全判断标准

如果一个环境截图在没有角色、UI、标题的情况下，仍然让人直接想到某个现成动漫、游戏或影视 IP，则必须重做。

安全环境应满足：看起来属于“星核拳馆”；以训练系统和读招功能为核心；没有现成 IP 的标志性构图、地貌组合、比赛场符号、建筑剪影；颜色、材质、布局都围绕《星核斗魂》的原创视觉规则。

#### 最终环境一句话标准

《星核斗魂》的环境必须让玩家第一眼理解：

> 这里是一个原创的星核能量拳馆；战斗者在清晰、硬派、可学习的空间中对练，胜负来自读招、距离和执行，而不是背景炫技或 IP 联想。

## 7. UI/HUD Visual Direction

### 7.1 UI/HUD 总原则

《星核斗魂》的 UI/HUD 应像“街机拳馆训练系统”的战斗读数，而不是科幻飞船仪表盘，也不是传统动漫格斗复刻界面。视觉核心是：

> **拳馆硬朗结构 + 星核能量读数 + 高对比即时反馈。**

UI 必须服务三个目标：

1. **一眼读懂战斗状态**
   - 血量、气槽、爆气状态、受击反馈必须比装饰更重要。
   - 玩家不应该需要思考：“我现在还能不能打？”、“气满了吗？”、“刚才为什么被打中？”
   - 关键信息必须在短时间内被识别，不能依赖长时间观察。

2. **强化“训练拳馆”身份**
   - UI 应像拳馆墙上的高端训练计分屏：硬边、清晰、耐用，带一点恒星能量反应。
   - 视觉语言来自擂台金属、训练灯、能量槽、冲击读数。
   - UI 不应像神秘魔法界面、宇宙战争雷达或手游奖励弹窗。

3. **只在关键瞬间使用高饱和能量**
   - 常态 UI 使用低饱和蓝黑、冷铁蓝灰、暗金。
   - 满气、爆气、重击、危险状态才允许出现星核金、核心金白、深红冲击、冷青信号。
   - 高亮必须短、准、局部，不能整屏长期发光。

4. **形状克制，层级清楚**
   - 使用硬边矩形、轻微切角、分段槽、细能量线。
   - 星核圆环只用于关键能量峰值，例如满气、爆气启动、胜负确认。
   - 避免大量复杂斜切、过细边框、高频小装饰。

5. **角色动作优先于 HUD 装饰**
   - HUD 应清楚但不遮挡角色动作。
   - 战斗角色的剪影、拳脚前摇、命中火花永远优先于 UI 装饰。
   - UI 不应占用角色上半身和主攻击路线。

---

### 7.2 Diegetic vs Screen-space：拳馆训练系统与屏幕 HUD 的边界

《星核斗魂》的 UI 分为两类：**拳馆内世界可见的训练系统视觉**，以及**玩家必须清楚读取的屏幕 HUD**。

#### 7.2.1 拳馆训练系统视觉

这些视觉可以被理解为存在于拳馆场景内，是环境的一部分：

- 擂台背景上的训练计分屏。
- 墙面或地面的能量监测灯带。
- 木桩或 CPU 训练目标身上的短暂命中读数。
- 地面边缘的回合提示灯。
- 爆气时场景内短暂亮起的星核能量线。
- 训练模式中的短暂环境提示，例如“破防”“反击”“确反成功”。

拳馆训练系统视觉应像真实训练设备，不像魔法符文；使用冷铁蓝灰 `#263241`、擂台蓝黑 `#090D18` 作为基础，冷青信号 `#39D6C8` 做系统提示，星核金 `#FFE76A` 和核心金白 `#FFF5C8` 只用于能量峰值。

#### 7.2.2 清晰屏幕 HUD

这些信息必须作为屏幕 HUD 固定显示，不应完全做成场景内物件：

- 玩家血量。
- 对手血量。
- 玩家气槽。
- 对手气槽。
- 回合时间。
- 当前回合数或训练状态。
- 低血量警告。
- 满气提示。
- 爆气状态。
- 暂停菜单。
- 训练调试 overlay。
- 键盘焦点状态。
- 胜利 / 失败结果。
- Web 浏览器失焦提示。

核心资源信息如果跟着场景透视移动，会增加理解成本。因此战斗核心 HUD 必须保持稳定、清晰、屏幕空间固定。

#### 7.2.3 二者结合方式

推荐方向是：

> **核心数值固定在屏幕 HUD，情绪反馈扩散到拳馆训练系统。**

示例：

- 气槽满时：HUD 气槽发出短促星核金脉冲，同时擂台边缘灯带闪一下。
- 爆气启动时：HUD 出现星核圆环扩散，角色周围有短暂金白能量压缩。
- 重击命中时：屏幕 HUD 给清晰命中标签，场景内用冲击灯和地面震线增强手感。
- 训练反馈：关键判定可以靠近角色出现，但最终信息仍应在 HUD 或 overlay 中可读。

---

### 7.3 HUD 布局方向

#### 7.3.1 信息优先级

战斗中玩家的注意力顺序应固定为：

1. **血量**：最高优先级，必须一眼看清双方剩余生命。
2. **气槽 / 能量槽**：第二优先级，应靠近血条，但亮度不能压过血量。
3. **可行动 / 硬直状态**：训练模式可明确显示，普通战斗中只做低干扰提示。
4. **输入反馈**：主要用于训练模式，放在侧边或角落。
5. **训练反馈**：命中、格挡、打空、距离、帧优势、连段计数，作为训练层信息处理。
6. **回合 / 计时**：顶部中央，重要性低于血量和气槽。

#### 7.3.2 总体布局

HUD 建议采用经典横向对战结构，但造型必须原创：

- 玩家信息在左上。
- 对手信息在右上。
- 时间 / 回合 / 训练状态在顶部中央。
- 气槽靠近血条下方或角色侧下方，但必须固定且清楚。
- 训练反馈在屏幕中上或中侧短暂出现，不能长期遮挡角色。
- 爆气、低血量等强状态用边缘提示，不用大面积遮罩。

整体视觉应像拳馆训练计分屏拆分成 HUD 模块：上方是战斗读数区，下方或血条下方是能量资源区，中央是回合与训练判定区，画面边缘是危险与峰值提示区。

#### 7.3.3 血条

血条是最重要的 HUD 元素。

- **形状**：硬边长矩形，轻微切角。
- **结构**：外框厚实，内部清晰填充。
- **底槽**：擂台蓝黑 `#090D18`。
- **外框**：冷铁蓝灰 `#263241`。
- **当前血量**：可使用偏暖暗金或低饱和暖色，但不要过于鲜艳。
- **受伤扣血**：即时血量快速减少，延迟损失段用深红冲击 `#B93A46` 短暂停留。
- **低血量**：血条末端出现深红冲击脉冲，外框可出现细小断续红线。

禁止：过度渐变、强玻璃质感、复杂纹样填满血条、现成街机格斗血条轮廓复刻、全屏红色滤镜常驻。

#### 7.3.4 气槽

气槽表达“星核能量积累”，但必须排在拳脚之后，不应比血条更抢眼。

- **形状**：分段槽，建议 3 到 5 段。
- **常态底色**：冷铁蓝灰 `#263241` 或擂台蓝黑。
- **未满状态**：低亮暗金 `#C28A38`。
- **接近满气**：星核金 `#FFE76A` 从分段边缘出现细线。
- **满气状态**：槽体短促星核金脉冲，中心可出现小型星核圆环，但只闪一次或低频呼吸。
- **使用气**：分段快速熄灭，有干脆的能量切断感。

禁止：巨大数字能量等级、长期火焰状外溢、过多圆形珠子式气格、类似现成动漫格斗符号的爆气 UI。

#### 7.3.5 状态提示

状态提示包括防御、破防、硬直、反击、冷却、爆气可用等。

- **位置**：角色附近可短暂出现，但重要状态需要在 HUD 中有稳定小图标。
- **颜色**：防御成功用冷青信号 `#39D6C8`；破防 / 重击用深红冲击 `#B93A46`；爆气可用用星核金 `#FFE76A`；冷却用冷铁蓝灰并降低亮度。
- **形状**：小型硬边标签、轻微切角、单色图标 + 少量高亮线。
- **文案**：短词优先，例如“反击”“破防”“满气”“冷却”。

状态提示必须像裁判和训练系统的精准判定，不像手游弹窗奖励。

#### 7.3.6 训练反馈

训练反馈要帮助玩家理解：是否看懂了对手前摇、是否在正确窗口防御 / 反击、是否因为贪招被惩罚、气槽和爆气选择是否正确。

推荐显示：

- “确反成功”
- “防御成功”
- “出手过早”
- “出手过慢”
- “被抓硬直”
- “距离不足”
- “可行动”
- “前摇”
- “收招”
- “命中硬直”
- “防御硬直”

规则：

- 训练反馈放在屏幕中上方、侧边或角色脚边低干扰区，不遮挡主动作。
- 成功反馈用冷青信号，完美反击等高价值正确反馈可加星核金。
- 失败反馈用深红冲击，但不要用惩罚性的满屏红字。
- 输入历史放在左侧或右侧边缘，最多显示最近 8–12 条。
- 距离提示可放在角色脚下或地面线上，但不得画一条穿过角色身体的高亮线。

训练反馈的气质应是“拳馆系统在教你读招”，不是“游戏在嘲讽玩家”。

#### 7.3.7 计时 / 回合信息

顶部中央建议放置计时与回合信息。

- **外形**：短宽硬边模块，可带轻微切角。
- **数字**：最大、最清楚。
- **常态颜色**：核心金白 `#FFF5C8` 或浅灰白。
- **背板**：擂台蓝黑 `#090D18`，边线用冷铁蓝灰。
- **低时间警告**：最后 10 秒可使用暗金到深红的边线变化，但数字不应剧烈抖动。
- **训练模式**：可将“回合”替换为“训练”“木桩”“CPU 脚本”等标签。

禁止使用过于复古的街机巨大圆形倒计时牌，以免接近经典格斗 UI 复刻。

#### 7.3.8 低血量、满气与爆气提示

- **低血量**：血条末端深红脉冲，屏幕边缘出现非常薄的红色断续线；禁止全屏红雾常驻。
- **满气**：气槽最后一段填满时，星核金沿分段线快速扫过，小型星核圆环扩散一次；“满气”标签出现后稳定，不一直跳。
- **爆气**：启动瞬间 HUD 气槽向外扩散星核圆环，角色周围短暂出现金白能量压缩；持续中只保留低频星核金呼吸；结束时金色线条逐段熄灭。

爆气视觉应表达“星核训练系统检测到短时间超压”，不是现成动漫变身语言。

---

### 7.4 Typography Direction：字体方向

字体必须支持中英文和数字的高可读性。整体性格应是：

> **硬朗、清晰、工业训练感、带一点街机速度感，但不过度复古。**

#### 字体性格

推荐字体气质：笔画清楚、结构方正、转角略硬、数字识别强、中文不拥挤、英文大写有力量。

避免：毛笔字、赛博乱码字、过度科幻窄体字、难读小号全大写长句。

#### 字重与大小层级

- **最大级**：计时数字、胜负结果。字重 Bold / Heavy，轮廓清楚。
- **中级**：血量名称、状态标签、菜单选项。字重 Medium / Bold。
- **小级**：训练 overlay 说明、调试字段、辅助文字。字重 Regular / Medium，但不能低于可读尺寸。

建议最低可读尺寸：

- 核心 HUD 数字、血量提示、回合计时：不低于约 24px 有效高度。
- 次级 HUD 文本：不低于约 18px。
- 训练 / 调试小字：不低于约 16px。

#### 中文可读性

中文标签应短、硬、明确：

- “防御”
- “破防”
- “反击”
- “满气”
- “爆气”
- “冷却”
- “失误”
- “距离不足”

中文 UI 要避免字体太窄、笔画粘连、发光描边过重、过多竖排、超短时间闪过长中文。

#### 英文与数字可读性

数字必须特别清楚，尤其是计时器、连击数、伤害数值、帧窗口、训练数据、调试数值。

数字风格应避免 7 和 1 太像、0 和 O 太像、5 和 S 太像、8 在小尺寸下糊成一团。

---

### 7.5 Iconography Style：图标风格

图标应遵循“拳馆训练系统图标”方向：单色或双色为主、轮廓硬朗、形状简化、小尺寸清楚、统一线宽、少用复杂内部细节。

#### 拳图标

- 简化拳头剪影，拳面方硬，手腕可用短矩形表示。
- 不画成漫画夸张大拳头，不带火焰、闪电、龙形纹样。
- 常态使用冷铁蓝灰或核心金白，命中强化时短暂使用星核金。

#### 脚图标

- 使用清晰腿部轮廓或靴形符号。
- 下段攻击可用低位水平切线辅助。
- 高段 / 跳踢可用小箭头或高度标记，但必须简洁。
- 与拳图标保持同一线宽和边角处理。

#### 防御图标

- 使用硬边盾形或前臂格挡抽象形。
- 防御成功时出现短促冷青闪线。
- 破防时盾形断裂，颜色转深红冲击。
- 禁止使用传统奇幻盾牌造型过重的纹章感。

#### 爆气图标

- 小型核心圆点 + 断开的星核圆环。
- 星核圆环只用于爆气、满气、胜负确认等关键峰值。
- 颜色使用星核金，峰值点使用核心金白。
- 禁止做成龙形、火焰人形、雷达探测器、战斗力扫描器。

#### 命中、冷却、警示图标

- **命中**：短促斜切冲击线；重击用更厚的断裂冲击块；反击可叠加冷青判断角标。
- **冷却**：整体降饱和，使用冷铁蓝灰，可用分段环或小型进度切片表示恢复。
- **警示**：使用深红冲击，形状可为硬边三角警示 + 切角矩形边框，闪烁频率低。

### 7.6 UI Animation Feel：UI 动画感觉

UI 动画必须短、硬、准。整体节奏应贴合拳馆格斗：

> **进入快，停顿短，回收干净。**

不应使用柔软、弹性过强、拖尾过多的动画。UI 的动效像训练仪器读数，不像手游奖励弹窗。

#### 按钮动画

- 默认：冷铁蓝灰边框 + 深蓝黑底。
- 焦点：暗金待机灯边线亮起。
- 确认：星核金快速扫线。
- 禁用：低透明度冷铁蓝灰，无强光。
- 焦点切换用短线滑入；确认时边框快速收紧再释放；不使用大幅缩放弹跳。

#### 血条变化

- 受击瞬间当前血量立即切掉。
- 红色损失段短暂停留。
- 重击扣血时血条外框可轻微震一下。
- 连续受击不应每次大震，避免 HUD 混乱。

#### 气槽满

- 最后一段填满后，星核金沿槽体分段快速扫过。
- 小型星核圆环从气槽中心扩散一次。
- 角色附近可出现一条短促金白上升线。
- 满气持续时只保留低频呼吸光。

#### 受击反馈

- 血条边框短红闪。
- 命中标签快速弹入，立即稳定，再淡出。
- 重击时 HUD 模块可有 1 到 2 帧横向冲击感。
- 破防时防御图标断裂，深红冲击短闪。
- 禁止大面积 UI 抖动导致玩家看不清下一招。

#### 爆气动画

- 启动：气槽分段向中心压缩，核心金白点亮，星核圆环从 HUD 模块向外扩散。
- 持续：HUD 边线低频金色呼吸。
- 结束：金色线条分段断开，槽体回到冷铁蓝灰，留下短暂暗金余辉。
- 禁止长时间全屏震动、巨大数值爆表视觉、类似现成动漫爆气变身 UI 的符号组合。

#### 胜利 / 失败动画

- **胜利**：中央硬边结果牌，星核金边线从两侧锁定，核心金白闪一下后稳定，背景拳馆灯带短暂响应。
- **失败**：结果牌使用冷铁蓝灰底，深红冲击只用于失败边线或小型警示，画面稍微降饱和。

结果界面要保留热血感，同时符合“训练拳馆”身份。

---

### 7.7 菜单、暂停与训练调试 Overlay

#### 主菜单

主菜单应像玩家进入“星核拳馆训练系统”的入口。

- 背景：暗色拳馆、擂台局部、训练灯带、冷铁结构。
- 主标题：硬朗、清楚、带星核金核心亮点。
- 菜单按钮：硬边矩形、轻微切角、分段边线。
- 色彩：主背景使用擂台蓝黑；金色只用于标题核心、当前焦点、确认动效；冷青用于系统状态或训练模式标识。
- 构图：标题不要过度占屏，菜单选项清晰排列，背景角色或拳馆元素不能影响文字可读性。

#### 暂停菜单

暂停菜单必须清楚、快速、不中断理解。

- 半透明深蓝黑遮罩，但不要完全盖掉战斗画面。
- 保留角色当前姿势可见，让玩家知道暂停瞬间的双方状态。
- 中央或左侧出现硬边暂停面板。
- 当前选项用暗金 / 星核金边框、指示箭头或左侧能量线标识。
- 从暂停返回时可以使用短倒计时或“按键继续”。

#### 训练调试 Overlay

训练调试 overlay 是 MVP 很重要的工具，但视觉上不能像开发者控制台直接糊在游戏上。它应是拳馆教练面板。

- 使用半透明冷铁蓝灰面板。
- 信息分组清楚：当前状态、命中判定、防御判定、读招反馈、气槽变化、输入记录。
- 字体小但清楚，不要过密。
- 成功用冷青信号；危险 / 失败用深红冲击；能量峰值用星核金；普通字段用核心金白或浅灰。
- Overlay 必须可开关，开启时也不能遮挡角色主动作区域。
- 调试信息必须明确标注 “DEBUG” 或 “TRAINING”。

### 7.8 Web 键盘与可访问性规则

#### 键盘可用性

因为 MVP 是 Web / Browser、键盘优先，UI 必须支持以下规则：

- 所有菜单必须可用键盘操作。
- 方向键 / WASD 移动焦点。
- Enter / Space 确认。
- Esc 返回或暂停。
- 当前焦点必须有明显高亮，不能只靠鼠标 hover。
- 任何 tooltip、按钮说明、设定说明，都必须能通过键盘焦点或按键打开。
- 按键提示必须显示真实绑定，例如 `J 轻击`、`K 重击`、`L 气功`、`Shift 冲刺`。
- 关键战斗操作不要绑定到浏览器常用组合键，例如 Ctrl+R、Ctrl+W、F5。

#### 浏览器焦点丢失提示

当玩家点击页面外、切换标签页、浏览器失去焦点时，应出现清楚提示：

- “游戏已失去焦点”
- “点击画面或按任意键返回”

返回焦点后，不应立刻恢复战斗，最好需要一次确认或短倒计时，避免玩家吃亏。

#### 色盲与非颜色备份

颜色不能单独承载关键信息。

- 红 / 绿不能作为唯一状态区分。
- 蓝 / 黄不能作为唯一状态区分。
- 血量危险、气槽已满、可行动、硬直、命中、格挡、打空等状态，必须至少使用颜色以外的一种辅助表达：形状、图标、文字、动画节奏或音效。

示例：

- “气满” = 满格分段槽 + 星核图标点亮 + 短音效。
- “低血量” = 血条剩余变短 + 边缘脉冲 + 危险图标。
- “硬直” = 裂纹图标 + 状态文本，而不是只变暗。
- “命中 / 格挡 / 打空” 必须有不同形状、停顿、音效和文字反馈。

#### 闪烁限制

- 不使用长时间高频闪烁。
- 避免每秒超过 3 次的闪烁。
- 不使用整屏白闪、整屏红闪和连续强闪。
- 星核金和核心金白只能作为短时、局部、关键信息。

### 7.9 与生图 / 资产管线的一致性

UI/HUD 相关视觉在使用生图和资产生成时，必须保持《星核斗魂》的原创视觉身份：街机拳馆、恒星能量训练者、拳脚优先、星核能量辅助。

#### codex-gateway-imagegen 生成 UI 概念图时应包含

生成 UI 概念图、HUD mockup、菜单视觉参考时，提示词应包含：

- 原创 2.5D Web 格斗游戏 UI。
- 街机拳馆训练系统。
- 恒星能量训练设备。
- 硬边矩形。
- 轻微切角。
- 分段能量槽。
- 低饱和蓝黑金属界面。
- 星核金只用于关键高亮。
- 清晰可读的血条和气槽。
- 高对比但不高噪音。
- 键盘优先菜单焦点。
- 屏幕空间 HUD，适合 60fps Web 游戏。
- 不遮挡角色动作。
- 原创图标语言。
- 训练反馈 overlay。

提示词中应强调：**“拳馆训练计分屏 + 星核能量读数”，而不是“动漫战斗 UI”。**

#### codex-gateway-imagegen 生成 UI 概念图时必须禁止

提示词中应明确禁止：七龙珠风格、现成动漫 IP 风格、战斗力探测器、眼镜式扫描器、经典街机格斗 UI 复刻、拳皇/街霸/罪恶装备等具体作品 UI 复刻、龙形能量纹样、赛亚人式爆气符号、巨大能量数字战斗力读数、过度火焰气焰、魔法符文、复杂机甲驾驶舱界面、过细高频线框、大面积霓虹彩虹渐变、手游抽卡式奖励 UI、hover-only 按钮状态、文字不可读的小字号、长时间全屏发光效果。

#### UI 图标生成提示方向

生成图标时应强调：单色或双色图标、硬边剪影、小尺寸可读、统一线宽、轻微切角、拳馆训练系统符号、星核圆环只用于爆气 / 满气、无 IP 特征、无龙、无探测器、无经典动漫符号、透明背景或清晰深色底、适合 Godot 2D Canvas UI。

图标类别应保持统一风格：拳、脚、防御、破防、爆气、命中、冷却、警示、训练反馈。

#### generate2dsprite 与 UI 的边界

`generate2dsprite` 主要用于角色精灵、角色动作、打击姿态、角色相关特效参考。它不应主导完整 UI 版式。

角色特效和 HUD 特效要区分：

- 角色爆气特效：围绕角色身体和动作。
- HUD 爆气提示：围绕气槽、边框、状态标签。
- 角色命中特效：表现拳脚冲击。
- HUD 命中标签：表现判定结果。

#### generate2dmap 与 UI 的边界

`generate2dmap` 主要用于拳馆背景、擂台空间、墙面训练屏、环境灯带、地面能量线、场景内训练设备。

它可以包含场景内的“拳馆训练系统视觉”，但不应负责核心屏幕 HUD。不应在地图图像中直接画死玩家血条、对手血条、实际气槽、计时器、暂停菜单、战斗状态标签、训练 overlay 文字。

这些信息必须在 Godot UI 中动态更新，并保持不同分辨率下清晰可读。

### 7.10 IP Safety：原创性与避让规则

《星核斗魂》可以有高速动漫能量武斗感，但 UI/HUD 不能暗示或复刻任何现成 IP。尤其要避免七龙珠式、经典街机格斗式、具体商业作品式的视觉组合。

#### 必须避免的方向

必须避免：

- 七龙珠式战斗力计量器。
- 探测器 / 眼镜扫描器 UI。
- “战斗力数值爆表”读数。
- 龙形、龙珠、愿望球、气焰变身符号。
- 赛亚人式金色爆气剪影。
- 经典街机格斗血条复刻。
- 拳皇式 UI 框架复刻。
- 街霸式血条与回合板复刻。
- 罪恶装备式高装饰摇滚 UI 复刻。
- 现成动漫格斗游戏的爆气图标结构。
- 使用具体 IP 的字体、配色组合、图标轮廓。
- 把“能量”表现成某个已知作品的标志性气场。

#### 可以保留的通用格斗信息结构

以下属于格斗游戏通用信息结构，可以使用，但必须用《星核斗魂》的视觉语言重新设计：左右对称血条、顶部中央计时器、气槽 / 能量槽、回合提示、连击数、命中 / 防御 / 反击提示、暂停菜单、训练反馈面板。

关键不是“不能有血条”，而是不能让血条轮廓、颜色、动效、图标组合看起来像某个现成游戏。

#### 《星核斗魂》的原创 UI 锚点

为了保持原创性，UI/HUD 应反复使用以下自有锚点：

1. **星核拳馆**：UI 像拳馆训练系统，而不是外星战斗雷达。
2. **拳脚先于能量**：拳、脚、防御、反击图标必须比纯能量符号更基础。
3. **分段槽与硬边训练设备**：气槽、按钮、血条都采用硬边矩形和分段结构。
4. **冷暗拳馆 + 局部星核高亮**：基础是蓝黑和铁灰，金色、金白、红色、冷青只在关键状态出现。
5. **读招定胜负**：UI 的最终目的不是炫，而是帮助玩家读懂危险、反击窗口、气满、爆气、命中与失败原因。

#### 最终视觉判断标准

任何 UI/HUD 方案都应通过以下判断：

- 看 1 秒，是否知道血量和气槽？
- 看 1 秒，是否知道当前是否危险？
- 看 1 秒，是否知道能不能爆气？
- 是否像“星核拳馆训练系统”？
- 是否让拳脚动作比能量装饰更重要？
- 是否避免了现成动漫 IP 的标志性符号？
- 在 Web 小窗口下是否仍然清楚？
- 键盘操作时是否能清楚看到焦点？
- 高饱和颜色是否只用于短时、局部、关键信息？

如果答案不是明确的“是”，则该 UI/HUD 方向需要收敛、降噪、增强可读性，或移除潜在 IP 暗示。

## 8. Asset Standards

### 资产标准总规则

《星核斗魂》的资产标准以 **Web 轻量、格斗可读、原创安全、可复用生产** 为核心。美术资产可以热血、发光、有冲击力，但任何资产如果降低出招方向、命中点、硬直窗口、血量气槽或键盘操作可读性，都必须降噪、缩小、减帧或重做。

当美术理想与技术预算冲突时，**技术预算是硬上限**；只有在目标浏览器实测 60fps 稳定、UI 和战斗读招不受影响时，才允许单项资产临时突破预算。

### 资产分类

MVP 资产分为 6 类：

| 类别 | 用途 | 生产优先级 |
|---|---|---|
| `char` | 玩家、训练木桩、影练 CPU | 最高 |
| `env` | 星核拳馆擂台、背景层、地面、远景结构 | 高 |
| `vfx` | 命中火花、能量尾迹、爆气、地面冲击 | 高 |
| `ui` | HUD、血条、气槽、按键提示、菜单框体 | 高 |
| `icon` | 状态、按键、调试标记 | 中 |
| `prompt` | 地图、角色、VFX、UI 的生成提示词与记录 | 中 |

MVP 首批资产只做能验证核心循环的最小集合：1 个均衡武斗家、1 个训练木桩、1 个影练 CPU、1 张星核拳馆训练擂台、基础 HUD、基础命中 / 防御 / 爆气 VFX。

### 文件格式标准

| 资产类型 | 交付格式 | 源文件格式 | 备注 |
|---|---|---|---|
| 角色逐帧 sprite | `.png` 透明背景 | `.aseprite` / `.psd` / `.kra` / `.clip` | 进入 Godot 前必须清理透明脏边 |
| 角色 sprite sheet | `.png` | `.aseprite` / `.psd` / `.kra` | 用于 Godot 导入和动画切帧 |
| 环境背景层 | `.png` | `.psd` / `.kra` / `.clip` | 分层导出，不把前景遮挡和背景烘死在一张图里 |
| VFX 序列帧 / sheet | `.png` 透明背景 | `.aseprite` / `.psd` / `.kra` | 必须保留清楚中心点和持续帧数 |
| UI / icon | `.png` 透明背景 | `.svg` / `.psd` / `.kra` | UI 必须能打包进 atlas |
| Prompt / 生成记录 | `.md` / `.txt` | 同交付格式 | 必须记录工具、用途、日期、IP 风险检查 |

禁止把未清理、未命名、未记录来源的 AI 生成图直接导入 Godot 作为正式资产。

### 命名规则

所有资产文件使用小写英文、下划线分隔，不使用空格、不使用中文文件名、不使用 `final`、`new`、`test` 等不可追踪词。

命名格式：

```text
[category]_[subject]_[action-or-role]_[variant-or-index].[ext]
```

示例：

```text
env_starcore_gym_ring_base_large.png
env_starcore_gym_bg_far_01.png
char_player_balanced_idle_01.png
char_player_balanced_heavy_punch_03.png
char_dummy_training_hit_light_01.png
char_shadow_cpu_attack_tell_01.png
vfx_starcore_hit_burst_small_01.png
vfx_starcore_guard_spark_02.png
ui_hud_healthbar_base_medium.png
ui_hud_energy_meter_fill_starcore.png
icon_input_key_attack_light.png
prompt_generate2dmap_starcore_gym_v01.md
prompt_generate2dsprite_player_balanced_v01.md
```

版本号只用于 prompt、源文件或批量迭代记录；正式运行时资产文件名优先表达类别、对象、动作和序号。

### 分辨率与纹理预算

#### 角色 sprite 单帧

| 资产 | 建议尺寸 | 硬约束 |
|---|---:|---:|
| 玩家站立 / 移动 / 防御帧 | `256 × 256 px` | 不超过 `320 × 320 px` |
| 玩家攻击 / 跳跃 / 受击帧 | `320 × 320 px` | 不超过 `384 × 384 px` |
| 玩家大招关键帧 | `384 × 384 px` | 不超过 `512 × 512 px`，且只用于极少数关键帧 |
| 训练木桩 | `192 × 256 px` | 不超过 `256 × 256 px` |
| 影练 CPU | `256 × 256 px` | 不超过 `320 × 320 px` |

角色 silhouette 必须在实际战斗镜头中清楚；不得用更大画布掩盖动作设计不清的问题。

#### Sprite sheet

| 资产 | 建议尺寸 | 硬约束 |
|---|---:|---:|
| 单个基础动作 sheet | `1024 × 1024 px` | 不超过 `2048 × 1024 px` |
| 单个复杂动作 sheet | `2048 × 1024 px` | 不超过 `2048 × 2048 px` |
| 单角色单阶段常驻载入纹理 | 约 `2048 × 2048 px` 等效面积内 | 超过需拆分并按状态加载 |
| 单张角色 sheet | 不超过 `2048 × 2048 px` | 禁止默认使用 4K sheet |

#### VFX sheet

| VFX | 建议尺寸 | 硬约束 |
|---|---:|---:|
| 小型打击火花 | `512 × 512 px` | 不超过 `1024 × 512 px` |
| 拳脚能量尾迹 | `1024 × 512 px` | 不超过 `1024 × 1024 px` |
| 地面冲击 / 裂纹 | `1024 × 1024 px` | 不超过 `2048 × 1024 px` |
| 小型气爆 / 星核闪光 | `1024 × 1024 px` | 不超过 `2048 × 1024 px` |
| 大招局部爆发 | `2048 × 1024 px` | 不超过 `2048 × 2048 px` |
| 全屏 VFX | 默认禁止 | 只允许极短转场或胜利演出验证 |

#### 环境背景

| 背景层 | 建议尺寸 | 硬约束 |
|---|---:|---:|
| 主训练擂台背景 | `1920 × 1080 px` 或更低 | 不使用 4K 背景 |
| 远景层 | `1280 × 720 px` | 细节必须弱于角色 |
| 中景拳馆结构层 | `1920 × 1080 px` | 不得与角色轮廓抢对比 |
| 单场景背景总纹理 | 2–3 张 `2048 × 2048 px` 等效面积内 | 超过必须删层、压缩或合并 |

#### UI atlas

| UI 资产 | 建议尺寸 | 硬约束 |
|---|---:|---:|
| HUD 主 atlas | `1024 × 1024 px` | 常驻 HUD 尽量 1 张 atlas 内完成 |
| 字体 / 数字图集 | `512 × 512 px` | 不为少量数字创建多张独立图 |
| 按键提示图标 | `512 × 512 px` | 小图标必须统一风格和边距 |

### Web 运行预算

| 项目 | MVP 预算 |
|---|---:|
| 目标帧率 | 60fps |
| 单帧预算 | 16.67ms |
| 常驻角色数量 | 1 名玩家 + 1 名训练木桩或影练 CPU |
| 常驻背景层 | 3–5 层 |
| 常驻 HUD 层 | 1–2 层 |
| 普通状态同屏短时 VFX | 3–6 个 |
| 爆发状态同屏短时 VFX | 不超过 10 个 |
| 普通状态粒子数量 | 50 以下 |
| 爆发瞬间粒子数量 | 150 以下 |
| 全屏透明叠加层 | 默认 0，特殊瞬间最多 1 层 |
| 常驻 CanvasItem 数量 | 尽量控制在 100 以内 |
| 大面积透明覆盖 | 尽量不超过屏幕面积的 25–35% |

爆气、命中和大招可以有峰值，但峰值必须短、局部、可读，不能变成常驻发光噪音。

### MVP 动画集合

#### 玩家：均衡武斗家

| 动作 | 最小用途 | 备注 |
|---|---|---|
| `idle` | 待机读姿态 | 站姿体现拳馆训练感 |
| `step_forward` | 前进 | 脚底不抖动 |
| `step_back` | 后退 | 与前进清楚区分 |
| `jab` | 轻拳 | 短前摇、清楚拳端 |
| `heavy_punch` | 重拳 | 更大蓄力和收招形 |
| `kick` | 中距离腿击 | 腿部轮廓必须清楚 |
| `guard` | 防御 | 手臂 / 身体角度一眼可读 |
| `block_react` | 防御受击 | 与普通受击区分 |
| `hitstun` | 受击硬直 | 不夸张到遮挡碰撞理解 |
| `knockback` | 击退 | 清楚表现方向 |
| `energy_focus` | 蓄气 / 聚焦 | 小范围局部星核光 |
| `energy_burst` | 爆气反杀峰值 | 不改变发型、体型、服装轮廓 |

#### 训练木桩

| 动作 | 最小用途 |
|---|---|
| `idle` | 默认站立 / 运行状态 |
| `hit_light` | 轻击反馈 |
| `hit_heavy` | 重击反馈 |
| `reset` | 回正 / 复位 |

#### 影练 CPU

| 动作 | 最小用途 |
|---|---|
| `idle` | 默认影练姿态 |
| `step` | 简单移动 |
| `attack_tell` | 攻击前摇提示 |
| `attack` | 基础攻击 |
| `guard` | 防御 |
| `hitstun` | 受击 |

动画数量优先服务读招，不追求长连段或复杂变身。每个动作都必须能标出前摇、活跃、收招和可打断 / 不可打断阶段。

### Pivot、对齐与切帧规则

| 资产 | Pivot 标准 |
|---|---|
| 玩家角色 | 脚底中心 |
| 训练木桩 | 底部中心 |
| 影练 CPU | 脚底中心 |
| 命中 VFX | 命中中心 |
| 爆气 / 星核 VFX | 爆发中心 |
| UI 元件 | 元件中心或布局锚点 |

角色帧可以 trim 空白，但不得造成脚底、身体中心或拳脚端点抖动。若 trim 后 pivot 难以稳定，宁可保留固定画布，也不要让动画在 Godot 中跳动。

### Godot 导入与材质约束

- 默认使用 Godot 2D Canvas 的普通 Sprite / Texture 流程。
- 角色、VFX、UI 优先使用透明 `.png`，背景使用分层 `.png`。
- 常驻角色资产尽量共用材质，避免每个动作、每个 VFX 都创建独立材质。
- Shader 只用于必要的局部能量、命中闪烁、UI 高亮，不用于大面积常驻背景炫光。
- Additive / transparent blend 必须克制使用，防止 Web overdraw 过高。
- 导入前检查 filtering、mipmaps、压缩、透明边缘和颜色偏移。
- UI 图标和 HUD 元件应打包 atlas，不把大量零散小 PNG 常驻加载。

### 战斗判定配套要求

战斗命中不能依赖 sprite 边缘。每个攻击动作必须能配套输出或标记以下信息：

- 前摇开始帧。
- 出手帧。
- 活跃命中帧。
- 收招帧。
- 攻击方向。
- 攻击范围参考。
- Hurtbox 参考区域。
- VFX spawn point。
- 命中火花中心。
- 防御火花中心。

美术帧和 hitbox / hurtbox 数据可以不同步于视觉边缘，但不能制造“看起来打到了却没打到”或“看起来没碰到却命中”的常态错觉。

### AI 生图管线标准

本项目美术资产生产路线固定如下：

1. 地图、场景、擂台布局需求先走 `.claude/skills/generate2dmap`。
2. 角色、sprite、动画帧、美术资产需求先走 `.claude/skills/generate2dsprite`。
3. 具体游戏生图入口统一走 `.claude/skills/codex-gateway-imagegen`。

三者分工：

| Skill | 负责内容 | 禁止事项 |
|---|---|---|
| `generate2dmap` | 地图结构、图层需求、战斗空间、环境约束 | 不直接绕过 Art Bible 做泛化场景图 |
| `generate2dsprite` | 角色、动画帧、sprite sheet、美术资产约束 | 不生成带现成 IP 特征的角色 |
| `codex-gateway-imagegen` | 按已约束 prompt 生成概念图、单个资产、VFX、UI 草案 | 不用未审查 prompt 直接产出正式资产 |

每个 AI 生成资产必须有记录：

```text
Tool:
Prompt file:
Generated date:
Asset purpose:
Target category:
Approved palette:
Resolution:
Status: draft / approved / rejected / needs paintover
IP safety checked: yes / no
Readability checked: yes / no
```

生成图只能作为草案、参考或需二次清理的源素材。进入 Godot 前必须经过命名、裁切、透明边清理、色彩检查、读招检查和 IP 安全检查。

### IP 安全标准

资产不得出现以下高风险特征：

- 七龙珠式尖刺发型、金发金焰变身、橙蓝主角配色、蓝白经典气功波构图。
- 现成动漫、格斗游戏、电影、漫画角色的服装、发型、标志、招式姿势或 UI 标识。
- 战斗力探测器、经典战斗服轮廓、可识别符号、标志性场景复刻。
- 拳皇、街霸、罪恶装备等作品的 UI 框架、字体组合、角色剪影或舞台构图复刻。

可借鉴的是“高速、热血、能量武斗、街机对战”的抽象体验，不可借用具体可识别表达。

### 资产验收 Checklist

资产进入正式原型前必须满足：

- 文件名是否符合命名规则？
- 文件是否放入正确类别和目录？
- 是否记录了来源、工具、prompt 和状态？
- 是否符合锁定色彩系统？
- 高饱和颜色是否只用于短时、局部、关键信息？
- 黑白剪影下是否仍能读出角色状态和攻击方向？
- VFX 是否没有盖住拳脚端点、命中点和受击方向？
- 背景是否弱于角色和 HUD？
- UI 是否能在 Web 小窗口清楚识别？
- 是否能键盘操作并看清焦点？
- 是否满足 Web 分辨率、atlas、overdraw 和粒子预算？
- 是否有明确 pivot 和对齐规则？
- 是否能配套 hitbox / hurtbox / VFX spawn point？
- 是否通过原创 IP 安全检查？

如果任一项答案不是明确的“是”，该资产只能保持 draft 状态，不能进入正式原型。

## 9. Reference Direction

本节定义《星核斗魂》的参考方向。参考的目的不是复制某个作品的外观，而是拆解可用的视觉原则：读招清晰、拳馆可信、能量克制、HUD 可读、Web 轻量、IP 安全。

所有参考都必须服从前 1–8 节的总规则：

> 像“街机拳馆中的恒星能量训练者”。先拳脚、后能量；当热血酷炫和格斗可读性冲突时，永远选择可读性。

### 9.1 参考使用边界

#### 可以借鉴

- 构图原则：横向对战空间、中心战斗区干净、背景后退、角色剪影优先。
- 色彩原则：深色环境承托局部高亮，暖色表达爆发，冷色表达训练 / 防御 / 系统反馈。
- 光影原则：角色和拳脚端点优先，背景光源低亮，爆发光短时集中。
- 动作原则：预备、释放、命中、收招四段清楚；每一帧都能看出攻击方向。
- UI 原则：血量、气槽、时间、状态提示稳定可读；装饰永远低于信息。
- VFX 原则：能量围绕拳脚、命中点、防御面和爆气核心组织，不独立表演。
- 背景层级原则：战斗读取层 > 拳馆身份层 > 星核氛围层。

#### 禁止借鉴

- 禁止引用或复刻七龙珠角色形象、尖刺发型、橙蓝道服、赛亚人战甲、金发金焰变身、双手前推大型气功波、荒野岩山战场、武道会擂台、精神时光屋式纯白空间等可识别表达。
- 禁止复刻拳皇、街霸、街头霸王、罪恶装备等经典格斗游戏的角色轮廓、UI 框架、字体组合、血条样式、舞台构图、招式姿势或标志性 VFX。
- 禁止“像某某角色但换颜色”“把多个知名角色元素混合一下”“参考某作品整体风格”的设计方法。
- 禁止在生图 prompt、资产文件名、角色说明或 UI 规格中把现成 IP 当作直接视觉目标。
- 禁止让任何截图第一眼看起来像现成动漫、游戏、电影或漫画 IP。

本节中的参考名称只用于内部研究和原则拆解，不得直接写入正式生成提示词作为风格目标。

### 9.2 参考互补矩阵

| 参考方向 | 主要服务内容 | 不承担的内容 |
|---|---|---|
| 格斗游戏通用读招体系 | 动作可读性、HUD 信息结构、攻防反馈层级 | 不复制任何具体格斗游戏 UI、角色、招式或舞台 |
| 真实拳馆训练 + 运动转播图形 | 星核拳馆可信度、训练器材、计分屏、信息秩序 | 不做真实拳击模拟，不复刻拳击赛事包装 |
| 克制发光几何 | 深色空间中的低频光带、硬边科技感、场景内系统界面 | 不复制具体科幻电影的载具、战衣、符号或蓝色霓虹主视觉 |
| 图形冲击节奏 | 2D 冲击帧、硬边爆点、短时高对比 VFX | 不使用漫画网点、对白框、拟声字、蛛网符号或超级英雄姿态 |
| 手绘块面控制 | 风格化材质、明确色块、角色 / 背景分层、局部高亮 | 不复制神话题材、等距视角、装饰性 UI 或角色服装语言 |

这五类参考互补分工如下：

- **读招体系**决定“玩家怎么看懂战斗”。
- **拳馆与转播图形**决定“星核拳馆为什么可信”。
- **克制发光几何**决定“星核科技如何存在于场景里”。
- **图形冲击节奏**决定“命中、爆气、反杀如何热血但不遮挡”。
- **手绘块面控制**决定“Web 2D 资产如何低噪声、可读、可生产”。

### 9.3 具体参考方向

#### 9.3.1 格斗游戏通用读招体系

**可以借鉴的具体视觉元素：**

- **构图**
  - 使用稳定横向对战构图。
  - 双方角色始终围绕中心战斗区展开。
  - 角色脚底、距离、攻击方向必须比背景装饰更清楚。
  - 摄像机不做强透视变化，避免玩家误判前后距离。

- **动作可读性**
  - 每个攻击动作都拆成清楚的预备、释放、命中、收招。
  - 轻攻击动作短、端点清楚、VFX 小。
  - 重攻击动作幅度更大，身体蓄力方向明显，收招风险可读。
  - 防御姿势必须和待机姿势明显不同。
  - 受击姿势必须显示受击方向和硬直窗口。

- **UI / HUD**
  - 血量在顶部左右稳定显示。
  - 气槽靠近血量或角色侧下方，但不能比血量更抢眼。
  - 计时 / 回合信息放在顶部中央。
  - 命中、破防、反击、满气等提示短时出现，不长期遮挡角色。

- **VFX 处理**
  - 命中火花集中在接触点。
  - 防御火花贴近防御面。
  - 攻击拖尾沿拳脚方向展开。
  - 爆发效果只在关键帧达到峰值，随后快速回收。

**必须避免 / 必须偏离的内容：**

- 不复制任何具体格斗游戏的血条轮廓、能量槽结构、回合板、字体、角色框、胜利牌或连击显示。
- 不复制经典角色的站姿、攻击姿势、胜利姿势或标志性轮廓。
- 不使用拳皇、街霸、街头霸王、罪恶装备等作品的 UI 装饰密度、舞台构图、角色比例或招式剪影作为直接目标。
- 不把“通用格斗结构”误做成“某个经典格斗游戏的复刻皮肤”。

**转译到《星核斗魂》的星核拳馆语言：**

- 保留“左右血条 + 顶部计时 + 气槽 + 状态提示”的通用信息结构，但全部改写为“拳馆训练计分屏 + 星核能量读数”。
- 血条使用硬边矩形、轻微切角、冷铁蓝灰外框。
- 气槽使用 3–5 段分段槽，星核金只在满气和爆气启动时短促扫过。
- 角色动作以护手、鞋底、腰部星核计量带为读取锚点。
- 所有 VFX 都围绕拳脚端点、命中点、防御面和爆气核心组织。
- 结果画面像训练系统确认胜负，而不是复刻经典街机胜利 UI。

#### 9.3.2 真实拳馆训练 + 运动转播图形

**可以借鉴的具体视觉元素：**

- **构图**
  - 中央训练区域保持干净。
  - 器材、护具架、计时屏、灯架、墙面结构放在后方或边缘。
  - 地面使用边线、刻度、垫子分区帮助判断距离。
  - 左右边界清楚，但不做高亮墙面干扰战斗。

- **色彩**
  - 训练馆主体色偏低饱和：深蓝黑、冷铁灰、旧金属、磨损橡胶。
  - 计分和状态信息用少量高对比色。
  - 成功 / 可行动 / 训练反馈可以用冷青。
  - 危险 / 破防 / 低血量可以用深红，但不得大面积铺屏。

- **光影**
  - 顶部训练灯形成稳定主光。
  - 角色交战区比背景更清楚。
  - 背景器材处于低对比半暗状态。
  - 胜利时灯光可以略微升暖，失败时灯光降冷。

- **UI**
  - 计分牌式信息层级：核心数字最大，辅助信息分组清楚。
  - 字体硬朗、数字清楚，避免装饰性太强。
  - 面板像训练设备，不像手游弹窗。

- **背景层级**
  - 前景极少，避免遮挡。
  - 中景承载角色、VFX、脚底阴影和地面标线。
  - 背景只提供拳馆身份：护具架、打击桩、灯带、训练屏、稳定器。

**必须避免 / 必须偏离的内容：**

- 不做真实赛事拳击擂台复刻，不让画面变成普通拳击游戏。
- 不使用真实赛事品牌、赞助商广告、围绳大特写、裁判、观众席、电视转播角标复刻。
- 不使用传统武馆、宗教符号、家族徽章或武道大会式场景。
- 不让拳馆太现实，失去“星核能量训练”的原创识别。
- 不让背景器材过多，影响角色剪影和拳脚端点读取。

**转译到《星核斗魂》的星核拳馆语言：**

- 把真实拳馆的沙袋、护具架、计时屏转译为星核拳馆的训练木桩、能量靶机、墙面训练计分屏。
- 把运动转播计分图形转译为硬边 HUD：血条、气槽、计时、训练反馈分区清楚。
- 把地面训练刻度转译为低亮距离标线、中央低亮星核圆环、冷青命中校准线。
- 把训练灯转译为暗金待机灯和稳定顶部暖光。
- 把运动数据反馈转译为“防御成功”“距离不足”“确反成功”“满气”等拳馆训练系统提示。

#### 9.3.3 克制发光几何

**可以借鉴的具体视觉元素：**

- **构图**
  - 大面积深色负空间承托少量发光线。
  - 场景结构以直线、矩形、圆环、清晰边界组织。
  - 发光元素沿建筑结构、地面边线、设备轮廓出现，不随机漂浮。

- **色彩**
  - 深色底面 + 局部高亮的对比方法。
  - 冷色系统光可以用于训练反馈。
  - 暖色核心光可以用于星核能量峰值。
  - 高亮色只在关键节点出现，不铺满画面。

- **光影**
  - 发光线条有明确来源：地面导线、设备边缘、核心节点。
  - 背景发光保持低频、低亮、低饱和。
  - 主体角色和战斗 VFX 永远比环境发光更重要。

- **UI**
  - 界面形状可以使用硬边、切角、细线、分段槽。
  - 圆环只用于核心能量状态，不到处滥用。
  - 面板应有仪器感、秩序感和清楚分组。

- **背景层级**
  - 远景光带用于空间深度。
  - 中景光带用于边界和训练设备。
  - 战斗区地面光线必须压低亮度，不能穿过角色脚底造成误读。

**必须避免 / 必须偏离的内容：**

- 不复制发光战衣、身份盘、光轮、载具、头盔轮廓、蓝色霓虹主视觉。
- 不把整体做成纯蓝黑科幻世界。
- 不使用大面积蓝色发光网格，避免和冷青训练反馈混淆。
- 不让 UI 像飞船驾驶舱或电子竞技直播包装。
- 不让发光线条密到影响脚底距离、攻击方向和 HUD 阅读。

**转译到《星核斗魂》的星核拳馆语言：**

- 将“发光几何”收敛为星核拳馆的地面能量导线、训练设备状态灯、低亮星核圆环、墙面计量屏。
- 主色使用 Art Bible 锁定色：擂台蓝黑 `#090D18`、冷铁蓝灰 `#263241`、暗金待机灯 `#C28A38`。
- 冷青 `#39D6C8` 只用于训练反馈、命中区、可行动提示。
- 星核金 `#FFE76A` 和核心金白 `#FFF5C8` 只用于爆气、满气、强命中、胜利余温。
- 圆环不做科幻身份盘，而做“星核训练系统的能量调压环”。

#### 9.3.4 图形冲击节奏

**可以借鉴的具体视觉元素：**

- **动作可读性**
  - 关键动作帧姿态非常明确。
  - 快速运动中仍保留身体方向、重心和端点。
  - 冲击前后节奏分明：压缩、释放、命中、停顿、回收。
  - 通过一两帧强图形化处理制造打击记忆点，而不是长时间铺特效。

- **VFX 处理**
  - 命中点出现硬边爆点。
  - 冲击线沿攻击方向展开。
  - 强命中可以短暂使用高对比形状，但必须快速消失。
  - 速度感来自方向线、形状节奏和姿态，不依赖大面积模糊。

- **色彩**
  - 高饱和色用于瞬间强调。
  - 背景可短时降暗，帮助角色剪影跳出。
  - 重要爆点用明度对比，不只靠颜色区分。

- **构图**
  - 画面焦点集中在动作发生点。
  - 视觉线条引导玩家看向拳脚端点、命中点或受击方向。
  - 不在同一瞬间堆太多同等强度的图形元素。

**必须避免 / 必须偏离的内容：**

- 不使用漫画网点、印刷错位、对白框、拟声字、漫画分格、蛛网图形、蜘蛛符号。
- 不复制超级英雄跳跃姿态、城市摆荡构图或特定角色动作轮廓。
- 不使用大面积流行漫画色彩拼贴，避免破坏星核拳馆的深色训练场基调。
- 不让冲击图形变成长期遮挡角色的装饰。
- 不把“热血”理解成满屏字效、贴纸和夸张表情。

**转译到《星核斗魂》的星核拳馆语言：**

- 将图形冲击转译为星核命中火花、短斜线、压缩圆环、楔形冲击块、受击点核心闪。
- 轻击使用小型短斜线和短弧尾迹。
- 重击使用更厚的楔形冲击块和短暂压缩圆环。
- 爆气反杀使用“身体压低 → 腰带亮起 → 金白核心短闪 → 星核圆环外放 → 快速回收”的节奏。
- 背景短时降暗只用于爆气或强命中，不作为常态滤镜。
- 所有图形冲击都必须保留拳脚端点、受击方向和硬直窗口。

#### 9.3.5 手绘块面控制

**可以借鉴的具体视觉元素：**

- **色彩**
  - 使用大色块建立主次，而不是依赖照片级细节。
  - 高亮色集中在焦点区域。
  - 背景与角色色值分离明显。
  - 暗部保留色彩倾向，不使用死黑。

- **光影**
  - 角色、道具、环境通过明确明暗块面分层。
  - 高光是设计出来的形状，不是随机真实反射。
  - 局部发光服务焦点，不铺满全屏。

- **背景层级**
  - 背景材质可以有手绘磨损，但噪声受控。
  - 远景细节低于中景，中景低于角色。
  - 道具轮廓清楚，但不和角色争抢最高对比。

- **UI**
  - 面板可有厚实边框和材质感。
  - 装饰只用于强化身份，不破坏文字和数字阅读。
  - 图标简化后仍有明确外形。

- **资产生产**
  - 适合 2D Canvas 的静态图层。
  - 适合 Web：不依赖复杂实时材质、PBR、重粒子或高频纹理。
  - 有利于 generate2dmap 和 generate2dsprite 保持稳定风格。

**必须避免 / 必须偏离的内容：**

- 不复制神话题材、神祇服装、武器造型、肖像框、等距视角、华丽花纹 UI。
- 不使用过度装饰的边框、复杂人物插画构图或叙事肖像界面。
- 不让画面变成奇幻地下世界、神殿或冥界氛围。
- 不用鲜艳大面积多色系破坏《星核斗魂》的深色拳馆 + 恒星能量体系。
- 不让手绘纹理密度影响格斗读招。

**转译到《星核斗魂》的星核拳馆语言：**

- 环境采用手绘风格化、非 PBR、低噪声、低细节密度。
- 金属护具、地垫、墙面、训练器材用大块面和简化磨损表达。
- 角色服装保持深蓝黑和冷铁蓝灰主体，小面积暗金 / 星核金节点。
- 背景设备和地面标线降对比，角色剪影、拳脚端点、HUD 和 VFX 保持最高层级。
- UI 面板可以有厚实训练设备感，但边框、纹理和高光必须比文字和读数低一级。
- 胜利、失败、爆气状态通过局部色温变化表达，不做全屏装饰性插画演出。

### 9.4 IP Safety：参考使用硬规则

#### 9.4.1 参考不是目标图

任何参考都只能拆成“原则”，不能当成“目标图”。

错误写法：

```text
做成像某某作品的角色
做成像某某游戏的 UI
做成某某动画那种爆气
像某某角色但换颜色
某某作品 + 某某作品混合
```

正确写法：

```text
横向对战构图，中心战斗区干净
深色拳馆环境，小面积恒星能量高亮
拳脚端点清楚，命中 VFX 集中在接触点
硬边矩形 HUD，分段气槽，训练系统读数感
短时压缩圆环爆气，不改变角色发型、体型和服装轮廓
```

#### 9.4.2 七龙珠相关硬避让

《星核斗魂》不得出现以下可识别表达：

- 七龙珠式尖刺发型、放射状头发轮廓、高耸发冠。
- 爆气后金发、金焰、全身持续金色 aura。
- 橙蓝道服、龟派符号、赛亚人战甲、探测器类装置。
- 双手前推、蓝白直线大光束、长时间横向贯穿画面的气功波构图。
- 荒野岩山战场、天下第一武道会式擂台、精神时光屋式纯白无限训练空间。
- 角色姿势、招式蓄力方式、胜利姿势或变身演出让玩家直接联想到现成动漫角色。

星核爆气的正确方向是：

> 装备节点短促过载、腰部计量带点亮、护手和脚底局部星核金闪光、压缩圆环短时外放、角色姿态仍然清楚可读。

#### 9.4.3 经典格斗游戏硬避让

《星核斗魂》可以使用格斗游戏通用信息结构，但不得复刻具体作品表达。

禁止：

- 复刻拳皇、街霸、街头霸王、罪恶装备等作品的血条形状、能量槽布局、角色头像框、回合标识、字体组合、胜利界面。
- 复刻经典角色的身体比例、发型、服装轮廓、站姿、招式剪影。
- 复刻经典舞台的构图、观众席、擂台边界、背景标志、色彩组合。
- 使用具体作品的 UI 图标、能量符号、爆气标记或装饰纹样。

允许：

- 左右血条。
- 顶部计时。
- 气槽 / 能量槽。
- 回合提示。
- 命中 / 防御 / 破防 / 反击提示。
- 训练反馈 overlay。
- 暂停菜单。

前提是它们全部使用《星核斗魂》的原创视觉语言：硬边训练设备、冷暗拳馆、分段星核槽、局部恒星能量、高对比但低噪声。

#### 9.4.4 生图与资产 prompt 安全规则

生成地图、角色、VFX、UI 概念时，prompt 不应写入具体商业作品名作为风格目标。

Prompt 应写：

- 原创 2.5D Web 格斗游戏。
- 星核拳馆。
- 街机拳馆中的恒星能量训练者。
- 深蓝黑拳馆环境。
- 冷铁蓝灰训练设备。
- 暗金待机灯。
- 小面积星核金能量节点。
- 拳脚端点清楚。
- 短促局部 VFX。
- 硬边矩形 HUD。
- 分段气槽。
- Web 60fps 友好。
- 无可识别现成 IP 特征。

Prompt 不应写：

- 像七龙珠。
- 像拳皇。
- 像街霸。
- 像某某角色。
- 某某作品风格。
- 赛亚人式爆气。
- 经典气功波。
- 某某游戏 UI。
- 某某动画的角色轮廓。

### 9.5 Reference Direction 检查清单

每次使用参考方向前，必须回答以下问题：

- 这个参考借的是“原则”，还是借了“可识别表达”？
- 去掉参考名称后，描述是否仍然成立？
- 是否仍然符合“街机拳馆中的恒星能量训练者”？
- 是否仍然先读拳脚，再看能量？
- 角色剪影是否没有现成动漫 / 游戏角色联想？
- 发型、服装、配色、姿势、招式构图是否全部原创？
- 爆气是否是短时、局部、围绕装备节点的星核过载，而不是变身？
- 气弹和能量攻击是否避免了蓝白大型直线光束？
- HUD 是否像拳馆训练系统，而不是经典格斗 UI 复刻？
